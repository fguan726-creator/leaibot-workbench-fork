# PM、UI 与研发统一工作流

本文件定义同一设计 Skill 在不同角色中的输入、输出和交接边界。角色可以停在不同阶段，但不得维护不同规则。

## 1. 共同原则

- 只使用根目录 `SKILL.md` 指向的合同、组件、响应式、交互和验收规则。
- 以当前项目和已确认需求判断差异；POC、Figma 04、UAT 与历史截图只作为证据。
- 所有新增、变更、删除、受影响行为、保护范围和未决项进入同一差异记录。
- 涉及功能范围、数据语义、权限、路由或封板表面的取舍，确认后再进入设计或代码修改。
- 设计交付与研发实现使用相同页面 ID、页型、状态、断点和验收条目。

## 2. 角色输入与输出

| 角色 | 必需输入 | 必需输出 | 可以停止的位置 |
|---|---|---|---|
| PM | 最新项目基线、PRD/POC、业务目标、角色权限、数据和范围 | 差异清单、确认项、保护范围、验收标准；需要演示时可生成基于 Skill Vue 参考组件的独立原型 | 需求和关键取舍确认完成 |
| UI/UX | 已确认需求、页面矩阵、设计合同、当前组件和视觉证据 | 页面结构、组件映射、状态、响应式、交互、文案、无障碍和视觉验收说明；需要时输出独立 Vue 原型 | 设计方案与验收说明确认完成 |
| 研发 | 同一确认记录、同一页面合同、Skill 组件库、当前目标仓库源码 | 组件复用/映射结论、Vue 实现、必要测试、工程命令结果、运行证据和剩余风险 | 实现与约定验收完成 |
| 评审/QA | 确认范围、页面合同、实现版本、测试环境 | 可复现问题、严重级别、证据、通过/阻塞结论 | 证据和结论归档完成 |

## 3. 单一交接包

每个需求使用同一组字段，不再制作“设计版”和“研发版”两套文档：

1. 需求或变更编号。
2. 目标角色、业务对象和成功条件。
3. 基线页面 ID、路由、实现归属和页型。
4. 新增、修改、删除和保护范围。
5. 组件、字段、数据、权限和操作规则。
6. 初始、加载、空、错误、无权限、禁用、提交、成功、部分成功和陈旧数据状态。
7. Agent 关闭、默认和最大宽度下的内容槽响应式要求。
8. 键盘、焦点、语义、文案和危险操作要求。
9. PM/UI 验收标准与研发可执行检查。
10. 未决项、阻塞项、证据路径和最终结论。

## 4. PM 与 UI 阶段

1. 先执行基线对比，不直接把新 POC 当成目标版本。
2. 明确哪些内容是新增需求，哪些是对已确认行为的有意修改。
3. 在 `page-spec-coverage-matrix.md` 定位页面；缺失时先登记。
4. 使用一个主基础页型，必要时叠加一个专项变体。
5. 输出可实现的结构与状态，不只输出静态理想态截图。
6. 使用现有 token、组件和内容宽度断点；不要为交付另建视觉体系。
7. 把关键取舍交给用户确认；非关键细节可按合同继续完成。
8. 需要可运行原型时，先从 `assets/vue-content-slot-components/` 复制 C/B 组件并组合；原型输出与产品仓库分离。不能复用时才生成页面局部 A，且不得自动晋升为共享组件。

## 5. 研发阶段

1. 先读目标仓库的路由、页面、组件、CSS、store、composable、service 和适配层。
2. 读取 `content-slot-vue-library.md` 和注册表，对新增研发需求执行 `C → B → 组合 → Domain wrapper → A`，先复用项目中已验证的同合同组件。
3. 项目不存在对应组件时，将 Skill Vue 组件适配到项目共享组件层；保留项目既有 tokens、基础组件和工程依赖，不把 Skill 目录作为运行依赖。
4. 将统一交接包映射到现有实现；不要翻译成第二套开发规范。
5. 保留未被需求覆盖的行为和封板表面。
6. 使用 Vue 与 TypeScript 正常架构实现；不要直接导入 POC 全局 CSS 或静态运行时。
7. 对新增异步、权限和危险操作补齐失败、恢复、确认和幂等边界。
8. 运行目标仓库的 lint、严格类型检查、生产构建和壳层/UI smoke。
9. 将组件映射、代码结果、运行证据和剩余风险回写同一交接记录。

## 6. 证据与版本

- 源码检查、静态模板、截图、交互验收和真实数据验收是不同证据层级，不得互相替代。
- 历史截图保留原项目、日期和环境信息；没有重跑就保持历史状态。
- 新项目版本确认后，同时归档对应项目和统一 Skill 版本。
- 安装副本或项目内置副本只能由权威 Skill 生成；内容漂移时以权威 Skill 为准并重新分发。
- 使用 `<app-root>` 和仓库相对路径记录源码位置；不得写入个人用户名、用户目录、桌面路径、本地文件协议地址或本地调试 URL。
- 不使用项目或 Skill 指纹作为兼容门槛；通过源码检查、规则对比、一致性验证和工程测试判断是否可用。
