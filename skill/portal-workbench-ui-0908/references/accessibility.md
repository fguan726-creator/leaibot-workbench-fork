# 可访问性与可用性规范

## 1. 对比度

- 正文和标题使用 `--color-text`（当前 `#1F2329`），不再使用历史 `#252525` 作为另一套默认正文色。
- 说明文字使用 `--color-text-secondary`（当前 `#646A73`）。
- 辅助文字使用 `--color-text-tertiary`（当前 `#8F959E`），只用于占位、时间戳和弱信息，不承载关键决策信息。
- 禁用文字使用 `--color-text-disabled`（当前 `#ABABAB`），不得用于可点击或关键信息。
- 普通正文与背景的对比度至少达到 `4.5:1`；大号文字和必要 UI 图形至少达到 `3:1`。

## 2. 键盘焦点

- 所有可交互元素必须有可见焦点态。
- 焦点态使用 `--focus-ring: 0 0 0 3px var(--color-primary-subtle)`。
- 不要移除 outline 后不给替代焦点样式。

## 3. 键盘顺序

- Tab 顺序应符合视觉阅读顺序：顶栏 → 侧栏 → 页面主内容 → 浮层。
- 弹窗容器使用 `role="dialog"`、`aria-modal="true"` 并通过 `aria-labelledby` 或 `aria-label` 提供名称；打开后把焦点移入弹窗，Tab/Shift+Tab 在弹窗内循环，Esc 关闭，关闭后焦点回到触发元素。
- 弹窗打开期间，页面背景区域使用 `inert` 阻止鼠标和键盘交互，并同步 `aria-hidden`；关闭时必须恢复原属性，不能把背景永久留在不可访问状态。
- 右侧 Agent 收起时必须同时设置 `inert` 和 `aria-hidden="true"`，不能只把宽度设为 `0` 或关闭 pointer events；如果焦点位于 Agent 内，收起后返回顶部“AI 助手”触发按钮。
- 抽屉打开后，Esc 可关闭；关闭前如果有未保存内容应提示。

## 4. 图标与按钮

- 仅图标按钮必须有 Tooltip 和可访问名称。
- 危险按钮除了颜色，还要有明确文字或确认步骤，不只靠红色表达。
- loading 按钮禁止重复点击，并保留当前操作文案。

## 5. 表单错误

- 错误态不能只靠红色边框，需要错误文字。
- 错误文字要紧跟字段。
- 提交失败时，页面应滚动或聚焦到第一个错误字段。

## 6. 状态表达

- 状态标签使用文字 + 色彩 + 圆点，不能只靠颜色。
- 进度和配额要显示百分比或数值。
- Tooltip 不能承载必须阅读的关键信息；关键说明应直接展示。
