# 页型模板

本文件规定当前乐享 AI 工作台常见页面的标准结构。生成或评审页面时，先判断页型，再套模板。

通用业务内容槽先读取 `content-slot-design-contract.md`。本文件保留完整项目中的专项页型与当前业务映射，不覆盖内容槽合同中的范围、优先级和状态规则。

## 目录

1. 七类基础页型与模板资产
2. Dashboard / 门户首页 / AI 报告
3. List、Detail、Form、Settings
4. Empty、Log、Permission
5. Skill Hub 与企业客户管理
6. Local Preview

## 0.1 0825 基础页型选择

Figma 05 中的基础布局统一映射为七类，不再把每张业务画板当作独立规范：

| 基础页型 | 适用判断 | 必备骨架 |
|---|---|---|
| 标准列表 | 常用筛选不超过 3 个，稳定表格列 | 页头 → 单行筛选 → 工具栏 → 表格 → 分页 |
| 长筛选列表 | 4 个以上条件或需要高级筛选 | 页头 → 可展开筛选 → 条件摘要 → 表格 → 分页 |
| 数据看板 | KPI、趋势、分布和明细共同支持决策 | 页头/时间 → KPI → 主趋势 → 拆解 → 明细 |
| 业务表单 | 新建、编辑、审批录入或规则配置 | 页头 → 分组字段 → 校验 → 保存/取消 |
| 任务/导入 | 上传、批处理、异步计算或报告生成 | 说明 → 参数/上传 → 进度 → 结果 → 失败明细 |
| 分栏设置 | 局部对象导航与设置工作区联动 | 页头 → 左侧局部导航 → 右侧设置 → 分区保存 |
| 配置列表 | 规则、模型、渠道、数据源、Skill 对象管理 | 页头 → 分类/筛选 → 表格或卡片 → 状态操作 |

详情、日志、权限、AI 动态报告、Skill 创建等属于专项变体：先使用最接近的基础页型承载普通组件，再叠加本文件对应专项规则。不得同时混合多个主页型造成页面层级不清。

## 0. Assets 模板入口

`assets/page-template.html` 只用于校准三栏壳层，不承载业务页设计。新增或优化中间内容槽页面时，优先参考以下业务页型模板：

| 页型 | 模板资产 | 用途 |
|---|---|---|
| 标准列表 | `assets/content-list-template.html` | 3 个以内常用筛选、稳定列结构与分页数据 |
| 带摘要列表 | `assets/content-summary-list-template.html` | KPI 摘要、筛选、状态 Tabs、表格与分页的固定组合 |
| 长筛选列表 | `assets/content-long-filter-list-template.html` | 4 个以上条件、高级筛选与条件摘要 |
| 数据看板 | `assets/content-dashboard-template.html` | KPI、趋势、结构拆解与异常明细 |
| 业务表单 | `assets/content-form-template.html` | 新建、编辑、审批录入与规则配置 |
| 任务 / 导入 | `assets/content-task-import-template.html` | 上传、批处理、异步任务与部分成功 |
| 分栏设置 | `assets/content-split-settings-template.html` | 页面内局部导航与分区设置 |
| 配置列表 | `assets/content-config-list-template.html` | 规则、模型、渠道、数据源与 Skill 对象管理 |

七类基础模板与带摘要列表组合统一引用 `assets/content-template.css`，不得在单个模板中重新定义另一套 token、控件尺寸或表格密度。

专项变体继续使用：

- `assets/content-workflow-template.html`：多步流程工作区，适用于 Skill 创建、权限管理、审批申请与配置向导。
- `assets/content-report-detail-template.html`：AI 动态报告 / 详情页，适用于右侧 AI 展开的长报告、分析详情和结构化结论。

使用规则：

- PM 或 AI 新增样式时，先判断页面归属哪一类模板，再在模板框架内做业务适配。
- 允许创意设计页面，但创意必须发生在内容组织、数据表达、图表组合和业务交互层；不能改变工作台大框架、信息密度、页头尺度、卡片节奏、右侧 Agent 关系和缩屏裁切顺序。
- 所有模板的 PageHeader 到第一个业务区块统一为 `16px`；看板 KPI、Skill 创建与其他专项流程不得另设页头下间距，也不得叠加父级 gap 与 PageHeader margin。
- 不要把模板当成最终 HTML/JS 实现。最终仍必须落到 Vue 源码、现有 class/token 合同和当前项目路由中。
- 模板的视觉优先级低于目标 `<app-root>` 源码；如果模板与运行中项目冲突，以当前 Vue 项目的已确认行为和本 Skill 合同为准。

## 1. Dashboard / 概览页

适用：门户首页、运营总览、Query 分析、质量分析、流量分析、GMV 分析、GEO 看板、线索看板。

结构：

1. 页头：标题 + 描述 + 时间范围筛选 / 刷新。
2. 指标卡行：3~4 个 Stat Card，自适应栅格。
3. 图表区：趋势图 / 分布图 / 配额图；优先使用 `--chart-*`、`--chart-seq-*` 和语义图表 token。
4. 列表区：近期任务、异常告警、调用 Top 项，使用紧凑表格。
5. 告警条：如有配额预警或失败任务，放在页头下方。

规则：
- 指标卡数字用等宽字体和千分位。
- 图表不要过度装饰，网格线用 `--chart-grid`，坐标轴用 `--chart-axis`。
- 图表优先单色阶或协调的中低饱和色板，并保证类别辨识度；普通分类不要拼接高饱和原色，强红只用于失败、异常、风险等警示状态。
- 中间数据展示区的视觉规则必须全站复用：页面顶部 KPI、概览指标等主要信息色块使用基于主色推导的蓝、青、靛、紫四种极浅辅助渐变循环、细边框、轻阴影，有色辅助色 alpha 低于 10%（推荐 2.5%-8%），白色收尾可为 100%，颜色只做很轻的信息底；下方链路步骤、拆解项、二级统计块、图表卡、表格卡、筛选区、待接口占位和大面板保持白底；不要只在一个模块局部覆盖。
- 告警类信息用 Alert Banner，不要混入普通卡片标题。

### 门户首页变体

门户首页是工作台入口页，仍属于 Dashboard / 概览页，但不使用营销 hero。

结构：
1. 轻量页头：`联想门户工作台` 标题 + 1 句能力说明 + 右侧 `管理技能包` / `创建 Skill` 操作。
2. 能力卡：4 张等宽卡片，说明 AI 助手、运营分析、Skill 创建、技能包管理等核心入口。
3. 常用入口：白底列表按钮，左侧业务名，右侧短说明，点击跳转对应页面。
4. 基础流程：4 步流程卡，使用小号数字圆点和简短说明。

规则：
- 当前确认版左侧导航不展示 `首页` 父级目录；用户通过左上 Logo 返回门户首页，面包屑仍可展示 `首页 / 联想门户工作台`。
- 本期不展示 `今日工作流 / 4 个核心域联动` 面板；不要用旧工作流渐变面板填充首屏。
- 首屏必须是可操作的工作台，不做大图、口号、营销 CTA 或装饰插画。
- 能力卡和流程卡使用白底、细边框、`--radius-md`（8px）圆角和轻 hover；大型流程容器才使用 `--radius-lg`（12px），不要使用区间内任意值或大面积强色块。
- 常用入口必须保留真实页面跳转，不只展示静态文字。
- 默认打开右侧 AI 助手时，首页布局要能在 AI 面板挤压下自然换列。
- 首页页头卡保持纯白工作台容器，只用细边框、紧凑层级和按钮关系表达重点；不要加入低价值装饰洗色，也不能新增全局 CSS import 或把首页变成营销 hero。能力卡、常用入口和流程行必须继续保持工作台密度、白底/浅底、细边框、轻 hover 和可见键盘 focus。
- 常用入口和流程行需要设置 `min-width:0`，长中文说明使用设计好的省略或换行规则；`1280px` 且右侧 AI 面板打开时不得产生页面级横向溢出。

### AI 结果报告视图

触发来源：仅由右侧 AI 对话中的长篇数据、解读报告、复盘、日报/周报/月报或结构化分析触发；普通左侧导航不生成 AI 结果，仍只打开静态业务页签。

入口与位置：当前会话存在已打开结果时，在 Topbar 静态页签右侧显示单一 `AI 结果报告`选择器。不得在面包屑下方、`.page-content` 上方创建 `.workspace-tabs`、第二排动态页签或等价占位行。激活结果后，完整内容直接替换中间内容槽的当前静态页面视图；选择器只负责结果管理和切换。

选择器结构：默认显示 `AI 结果报告`、当前会话结果数和下拉箭头；激活结果后显示约 10 个中文字符的精简标题并以主色高亮。下拉项只放精简标题、来源、保存态、当前态和关闭入口；完整标题保留在可访问名称中。不得混入其他会话、未被当前消息引用的结果或历史时钟图标。

内容：临时报告打开后，中间内容槽渲染完整报告页。先按报告任务选择一个 T1–T7 主类型并叠加 V3，再使用内容槽组件库组合 `ContentPageHeader`、`SectionHeader`、`SectionCard`、按需的 `MetricGrid / MetricCard`、`ChartPanel`、`ContentTabs`、`ListSurface / DataTable / Pagination` 与 `FeedbackState`。保存 / 下载 / 关闭属于页面操作；退出按钮统一显示 `关闭`。点击后关闭当前 AI 结果，存在同会话相邻结果时切换到相邻结果，关闭最后一个结果后返回当前静态页面。正文必须将长 markdown 拆为结构化章节，不要在摘要下方再次原样堆出整段 markdown。报告页不改变左侧导航选中状态和面包屑父子关系。

版式：报告内容必须继承普通导航内容槽的宽度、字号和组件合同，随中间可用区域自适应填满，直接容器使用 `width:100%`、`min-width:0`、`max-width:none`，不要固定窄宽或居中形成大面积空白。页面标题必须复用 `ContentPageHeader` 的固定 icon、`19px` 主标题、`12px` 副标题和唯一 `h1`；模块标题复用 `SectionHeader` 的 `16px` `h2`；正文使用 `13px/14px` 的适用层级，指标遵守 `MetricCard` 合同。不要把报告页做成独立大字号阅读器。标题层级最多保留两处：选择器精简标题 + 内容主标题；摘要区只承载结论、标签和必要指标，不重复主标题。

组件边界：AI 结果的 `conversationId + messageId`、最多 10 个、切换、保存态、关闭和相邻结果回退属于动态页签容器；内容槽组件只负责呈现。不得给 Common 组件添加 `isAiReport` 或 `isDynamicTab`，也不得建立 AI 报告专用的 PageHeader/Card/Table 视觉方言。

背景：内容槽允许使用基于主色的极浅横向渐变，但必须连续、自然、无硬分割；不要使用固定高度 `background-size` 色带、1px 分割线、高光线或突然回灰的断层。渐变只作为很轻的画布层级，不能变成大面积饱和背景。

交互：从 AI 结论卡展开报告、通过选择器切换结果或返回静态页面时，中间内容槽应滚动到顶部，确保标题和 hero 首屏可见。

多开对比：同一 AI 会话可打开最多 10 个结果，并通过选择器切换。点击任一静态页签返回对应导航页面时，已打开结果继续保留；关闭当前结果时切换到同会话相邻结果，关闭最后一个结果后返回当前静态页面。

副标题文案：报告头部副标题只承担来源说明、页面来源和时间，不再额外提高字级或字重。视觉上必须与普通页面的 `page-desc` 保持一致，不能因为切换到 AI 结果视图出现“副标题更大、更粗、更蓝”的跳变。

## 2. List / 表格列表页

适用：职场员工审核、留言工单、线索池、员工列表、知识上传记录、来源明细。

结构：

1. 页头：标题 + 说明 + 右侧主操作。
2. 筛选栏：搜索框 + 筛选器 + 重置；复杂筛选可折叠“高级筛选”。
3. 批量操作条：选中行后出现。
4. 表格：普通业务列表默认 48px；只有明确的高密度单行任务/配置表使用 40px compact；操作列保持最右可达。
5. 分页器：底部右对齐，支持每页条数。

规则：
- 一个页面主按钮通常只出现一次。
- 表格状态必须覆盖加载、空、错误、无权限。
- 行内危险操作必须二次确认。
- 同一数据集的筛选、状态 Tabs、表格和分页使用 `ListWorkspace`；有 KPI 摘要时直接选用带摘要列表模板。禁止按截图逐块堆卡片并为每块单独补 margin。
- PageHeader → Summary/ListWorkspace 为 `16px`，Summary → ListWorkspace 为 `16px`，FilterBar → ListSurface 为 `12px`；ListSurface 内 Tabs/Toolbar → Table → Pagination 使用 `0px + border`。

## 3. Detail / 详情页

适用：留言工单详情、线索详情、职场员工审核详情、员工详情、知识条目详情。

结构：

1. 页头：返回 / 面包屑 + 对象名 + 状态标签 + 右侧操作。
2. Tabs：概览 / 配置 / 日志 / 版本 / 调用记录。
3. 主体：主从两栏或多个分组卡片。
4. 技术信息：ID、Key、JSON、日志等独立放入等宽面板。

规则：
- 对象名旁可放状态标签，但不要把状态写进标题。
- 配置项分组展示，避免长列表无层级。
- 日志和 JSON 不混入普通正文。

## 4. Form / 配置页

适用：分配线索、维护线索数据、转商机、导出审批、线索反馈、打分规则编辑、留言回访记录、认证状态修改。

结构：

1. 单列居中，容器宽 `--container-narrow: 720px`。
2. 分组卡片：每组一个 Card，字段标签在上。
3. 底部操作区：取消 / 保存，长表单可吸底。
4. 多步复杂配置使用 Steps / Wizard。

规则：
- 必填字段使用红星 + “必填”双重提示。
- 失焦校验为主，提交时全表兜底。
- 多字段编辑优先右侧抽屉；简单确认用居中弹窗。

## 5. Settings / 设置页

适用：账号、安全、成员、通知、系统配置、业务规则配置。

结构：

1. 左侧二级导航。
2. 右侧设置内容。
3. 每节一个卡片：标题 + 说明 + 控件 + 独立保存。

规则：
- 不同设置项不要共用一个全局保存按钮，除非确实属于同一配置组。
- 危险设置区与普通设置区分离，使用 danger 语义。

## 6. Empty / 引导页

适用：无留言工单、无线索、无审核记录、无知识条目、无权限可见内容。

结构：

1. 居中图标 / 插画。
2. 一句说明：为什么为空。
3. 一个主操作：下一步做什么。
4. 可选帮助链接。

规则：
- 不要只写“暂无数据”。
- 主操作必须明确，例如“新增线索”“创建回访记录”“上传知识”。

## 7. Log / 技术内容页

适用：日志、调试、运行记录、JSON 输出、API 响应。

结构：

1. 页头：标题 + 时间范围 / 级别筛选。
2. 工具栏：搜索、级别筛选、复制、导出。
3. 日志面板：深底、等宽、可滚动。
4. 错误详情：可折叠，避免直接占满页面。

规则：
- debug/info/warn/error 使用统一日志色。
- 长内容必须可复制、可横向滚动或折叠。

## 8. Permission / 成员权限页

适用：成员管理、角色配置、权限矩阵。

结构：

1. 页头：标题 + 邀请 / 新建角色。
2. 成员列表或权限矩阵表格。
3. 角色说明卡片。
4. 危险操作二次确认。

规则：
- 权限变更要提供明确反馈。
- 管理员、拥有者等关键角色使用标签标识。

## 9. Skill Hub / 技能管理页

适用：Skill Hub、Skill 包状态管理、平台 PM / 管理员审批、发布、启停、批量申请、评估验证、应用测试。

结构：

1. 页头：标题 + 说明 + 右侧 `创建 Skill` / `刷新` 等操作。
2. 摘要卡：全部、草稿、待审批、已发布、已禁用等状态计数。
3. 筛选栏：搜索 + 状态 + 分类 + 标签 + 重置。
4. 表格：名称、描述、版本、线上版本、状态、分类、标签、更新时间、操作。
5. 行内操作：查看、编辑、测试、提交审核、审批、发布、禁用、启用、删除等按权限/状态显示。
6. 弹窗：详情查看用大弹窗或抽屉；状态变更用确认弹窗；测试用评估验证弹窗。
7. 技能包申请：包选择卡片 + 业务审批人 + 系统审批人 + 申请理由 + 提交反馈。

规则：
- 这是数据管理页，不做卡片瀑布流；默认以表格为主，便于比较状态和版本。
- 状态标签统一浅底 + 实色文字 + 可选小圆点；状态色不得与危险操作混淆。
- 行内操作保持 12px 文字按钮或紧凑描边按钮，不能撑高表格行。
- 高影响操作（发布、禁用、删除、审批、驳回）必须二次确认并说明影响范围。
- 评估验证过程需要明确运行中、通过、失败、警告状态，完成后提供继续操作。
- 启停和申请功能不得改变 Skill Hub 的数据管理密度。开关、申请卡片、审批人下拉必须使用本地语义 token；当前发布按强制浅色验收，未来明确恢复深色时再补做专项验收。

## 10. 企业客户管理 / 线索管理页

适用：`线索看板`、`线索池`、`打分模型`、线索详情、分配、反馈、转商机、导出审批、数据维护。

结构：

1. 父级导航：当前 0825 Vue 项目使用 `企业客户管理`，子项为 `线索看板`、`线索池`、`打分模型`。
2. 线索看板：页头 + 角色视图切换 + 时间/团队/来源/产品筛选 + underline tabs + KPI / 漏斗 / 质量 / 团队图表。
3. 线索池：页头 + 角色视图切换 + 六张状态 KPI + 操作栏 + 筛选栏 + 紧凑表格 + 分配详情区。
4. 打分模型：页头 + 四张统计卡 + 新建规则工具栏 + 加分项 / 减分项规则表。
5. 短流程：分配、触达、反馈、转商机、导出审批、规则编辑优先使用 modal / drawer。

规则：
- 页面根部使用 `.lead-0615-page`，打分模型额外使用 `.lead-score-page`，样式必须受作用域限制。
- 角色切换是 segmented control，不是页面级 tab；页面级 tabs 只用文字 + active underline。
- 表格使用 `--text-sm`（13px），表头使用 `--text-xs`（12px）；线索评分规则表是高密度单行表，固定使用 `--row-height-compact`（40px）。宽表横向滚动，不压缩字段到不可读。
- 操作按钮使用产品文案：`导入线索`、`导出（脱敏）`、`导出（明文）`、`新建规则`、`删除`、`返回线索池`。不使用 emoji 前缀。
- 明文导出默认需要审批弹窗；手机号和敏感字段默认脱敏。
- 图表使用 Leaibot chart palette；ECharts 容器有稳定高度，并在筛选/tab 切换后 resize。
