## 1. 壳层与侧栏

- 侧栏展开 `168px`、收起 `58px`；Topbar `56px`；Agent 默认 `380px`、最大约 `492px`。
- 当前发布隐藏主题切换并强制浅色；底层 token 可保留，但不得泄漏历史深色偏好。
- viewport `<=1320px` 允许自动收起，`>=1480px` 只恢复系统自动收起的侧栏。用户手动收起不能被自动展开覆盖。
- 初始加载与 resize 使用同一判断；`1280px` 验收时侧栏为 `58px`，页面根横向溢出为 `0`。
- 每次完整打开或刷新工作台时，右侧 Agent 默认收起；用户通过 Topbar 右上角“AI 助手”展开。展开后在当前单页会话内切换业务路由不自动收起，仍由用户手动控制。
- 收起态必须是完整不可交互态：Agent 根节点设置 `inert` 与 `aria-hidden="true"`；收起前若焦点在 Agent 内，焦点返回 Topbar 的“AI 助手”按钮。
- Agent 展开、收起和拖宽会改变中间内容槽实际宽度。布局稳定后必须通知图表重算尺寸；ECharts/Canvas 等像素型组件使用 `ResizeObserver` 跟随自身容器，不得保留展开前的画布宽度。
- 收起态点击父级导航可临时 peek 子菜单；鼠标离开恢复。手动切换会取消 peek。
- 缩放顺序固定：内容槽按容器宽度降级 → 侧栏按壳层阈值收起 → Agent 约束。完整阈值见 `responsive-layout-contract.md`。
- 页面不得用固定主列、刚性 `minmax(640px/720px,1fr)` 或缺失 `min-width:0` 抢先制造裁切。

## 2. 静态页签与 AI 结果报告

统一术语：`静态页签`是由左导航叶子页面打开的路由页签；AI 结果是动态页签，是由当前 Agent 会话产生的报告、链接或 HTML 预览 artifact，也是动态页签的数据与交互对象；`AI 结果视图`是选中该动态页签后在中间内容槽中的完整页面；Topbar 单一 `AI 结果报告`选择器是动态页签的当前展示和管理入口。不存在第二排动态页签条，但动态页签的多开、切换、保存、关闭和会话归属机制仍然存在。`TempTabView.vue`、`tempTab` 等名称仅为现有实现标识，不代表可恢复 `.workspace-tabs` 或任何第二行页签 UI。

### 2.1 静态页签

- 左导航打开的是静态页签；面包屑保留业务域，右侧展示可多开的当前页面页签。
- 静态页签最多 10 个；打开第 11 个时关闭最早页签并轻提示。
- 页签超宽时容器横向滚动；打开、切换和渲染后 active 页签自动滚入可视区。
- 点击静态页签必须退出当前 AI 结果视图并返回静态页面，但不自动关闭当前会话中已打开的 AI 结果。
- 静态页签即使只剩最后一个也保留关闭入口；关闭最后一个活跃页签后回到 `/portal/home`，并恢复“首页 / 联想门户工作台”静态页签。
- 选中按钮保持 `28px`，不能撑高 `56px` Topbar。
- active 状态只以当前已解析路由的 `pageId` 为准；离开中的旧页面不得在卸载前重新写回 active 或重新打开自身页签。
- 页签标题激活与关闭是两个独立可访问操作：关闭入口使用独立 `button`、停止事件传播并且一次点击只触发一次关闭；不得在页签主按钮内嵌套交互元素。关闭当前页签时，移除、相邻页签选择与路由跳转必须作为一次原子交接完成。

### 2.2 AI 结果报告选择器

- AI 报告、HTML 预览和链接结果仍进入中间内容槽，不占左导航层级；入口合并为 Topbar 静态页签右侧的单一结果选择器，不再使用第二行动态页签。
- 当前会话存在已打开报告时才显示选择器。未激活报告时固定完整显示 `AI 结果报告`，使用中性 AI 渐变胶囊；激活后显示当前报告精简标题并以主色高亮。
- 报告标题去掉冗余 `AI 报告` 前缀和序号，显示约 10 个中文字符，超出显示省略号；完整标题保留在 `title` 与可访问名称中。默认文案不得被压缩或省略。
- 选择器只显示文字、当前会话结果数和下拉箭头，不使用历史时钟图标。下拉中保留来源、保存态、当前态、切换和关闭入口。
- 每份结果必须同时绑定 `conversationId` 与产生它的 assistant `messageId`。下拉仅展示当前 Agent 会话且被当前会话消息明确引用的结果；新建或恢复会话时退出原报告视图，绝不跨会话汇总。
- 同一会话最多 10 个结果；超限关闭最早结果并提示。关闭当前结果后只切换到同一会话的相邻结果，关闭最后一个后返回当前静态页。
- 静态页签在选择器出现时采用紧凑节奏：页签间距约 `3px`、单个页签水平内边距 `6px`，保持 `28px` 高度、关闭入口和横向滚动能力。
- 报告激活时，Agent“正在关注”显示报告精简标题；静态页激活时只显示页面名，不拼父目录。

### 2.3 AI 结果视图与内容槽组件库

- 选择器只管理动态页签；选中的报告、链接或 HTML 预览必须作为独立页面渲染在中间内容槽，完整遵守 `content-slot-design-contract.md`。
- 每个结果先按任务选择一个 T1–T7 主类型，再叠加 V3 AI 结果变体。报告通常使用 T3 或适配内容任务的主类型；链接与 HTML 预览也必须登记主类型，不能用“动态页签”替代页面结构判断。
- 页面结构按 `C → B → 组合 → Domain wrapper → A` 复用内容槽组件库。结果页必须使用 `ContentPageHeader` 作为唯一 `h1`；章节使用 `SectionHeader`，普通区块使用 `SectionCard`，指标、图表、Tabs、表格和反馈状态按 payload 实际需要组合。
- `conversationId + messageId`、结果数量、保存、关闭、相邻切换和返回静态页属于 AI 结果容器；数据请求、报告正文、原始 URL、iframe payload 和下载内容属于结果消费者。两者不得塞进 Common 视觉组件。
- 不建立“AI 报告专用按钮/卡片/表格”视觉方言，不给 Common 组件添加 `isAiReport`、`isDynamicTab` 等业务开关。确有专属结构时先建立 V3 组合或 page-local A，并登记升级条件。
- loading、empty、error、no-permission、stale 等适用状态使用 `FeedbackState`；Agent 开合和内容宽度变化继续执行内容槽响应式合同，页面根部横向溢出必须为 0。

## 3. Agent Composer、停止与队列

- Composer 是封板共享组件：快捷标签、附件 rail、输入行和提示属于一个圆角组，不拆成多个描边模块。
- 快捷标签为单行横向 pill rail，使用左右圆形箭头；不改成 Select、不换行、不设默认选中。
- 附件位于快捷标签和输入行之间，以可横滑 chip 展示；支持多文件、单个删除和图片预览，不使用大块预览卡。
- 输入行包含 icon-only 附件、默认 `36px` 自增长 textarea、单个 `32x32px` 发送/停止按钮。
- 浅色默认态中，外层输入组合件使用 `--color-surface-subtle`，可编辑输入行使用白色 `--color-surface`；textarea 自身透明并继承白色输入行，placeholder 使用 `--color-text-tertiary`。不得把整个默认输入区做成类似 disabled 的连续灰底。
- textarea 聚焦时仍保持白色，由外层组合件统一显示主色边框与 `--focus-ring`；空输入只灰化真正 disabled 的发送按钮，附件和 textarea 仍明确可交互。
- Agent 回答时输入仍可编辑。有文本再次发送进入独立队列；空文本时发送按钮变停止按钮。
- 队列显示在 Composer 上方，不混入聊天流；严格按“当前回答完成 → 下一条用户消息 → 对应回答”逐组执行。
- 停止只终止当前回答，不清空尚未执行的用户队列；停止和队列策略必须在界面中可理解。
- 本地预览允许模拟慢流式输出，以验证停止、队列和打字过程。

## 4. Agent 消息与过程状态

右侧 Agent 与 Skill 创建/需求澄清使用同一对话框架。

### 4.1 等待与正式回答

- 仅在尚未形成过程块时显示一行透明等待态：无背景、边框、阴影和气泡圆角。
- 已有“处理过程”块时不得再显示重复的“正在整理上下文”等待行。
- 正式 assistant 文本必须进入统一回答气泡；纯文本、报告卡、授权卡和操作卡都不允许裸露在面板背景上。
- 欢迎态是文档流入口，不按普通回答气泡处理。

### 4.2 当前过程块

- 过程块位于当前回答或授权请求的正上方，标题统一为 `处理过程`；不固定沉底、不放进答案气泡。
- 只渲染本次真实到达的状态：`thinking`、`tool_call`、`tool_result`、`follow_up`、`confirm`、`streaming`、`error`。普通问题不得插入演示专用卡片。
- 状态使用 `等待中 / 进行中 / 已完成 / 失败 / 待确认`；不展示真实 chain-of-thought，只展示可审计步骤。
- 默认最多展示 3 个当前 active/waiting 状态。已完成调用折叠隐藏；存在历史时保留展开/收起入口。
- `confirm` 由授权请求卡承载，不在过程块重复一张待确认卡。
- 完成、停止或失败后不得遗留无归属的 `running/pending`；下一条队列任务可在启动后拥有自己的运行态。
- 图标使用项目线性 SVG，不用 `◇`、`⌁`、`↝`、`?` 等字符残留。

### 4.3 输出节奏

- 普通和完整场景回答都使用轻量打字呈现；`prefers-reduced-motion` 下关闭非必要逐字与位移动效。
- 授权、报告、行动卡和 TODO 在相关文字出现后淡入，不得早于解释文本整块闪现。
- 动效只作用于 Agent 内容，不改变 header、Composer、队列、面板宽度或壳层。

## 5. 授权、TODO 与结构化结果

### 5.1 授权

- 导出、发布、写入、权限、审批和其他高影响动作在用户批准前不得执行。
- 授权请求卡位于 assistant 气泡内，包含标题、风险、命名空间、命令/参数预览、影响和批准/拒绝。
- 待确认说明写在普通回答文本中，不塞入命令卡；过程块不重复 `confirm`。
- 批准/拒绝后移除待确认过程状态，将结果卡回填到同一个回答气泡、请求卡下方，不追加重复解释气泡。

### 5.2 TODO

- TODO 位于当前回答之后，作为独立直接列表内容；不得再套 assistant 气泡、边框或卡片背景。
- 支持展开/收起，显示完成数/总数与逐项状态；全部完成后自动收起。
- TODO 不是消息队列，不能阻止 Composer 输入，也不能替代过程状态。

### 5.3 全场景验证

`全场景串联演示` 仅用于验证过程、能力卡、打字文本、授权、批准/拒绝、最终回答和 TODO 的组合。它是验证数据，不是所有真实查询的固定模板。

## 6. Skill 创建与权限管理工作区

- 两页采用固定工作台卡：顶部步骤、中部独立滚动内容、底部固定操作。
- 需求澄清区底部顺序固定：辅助标签 rail → 紧凑输入行 → 独立上一步/下一步流程行。
- 输入行附件、textarea、发送对齐约 `38px`；textarea 默认单行且不可拖拽破坏布局。
- 流程按钮单行、主次明确并统一靠右排列；权限管理与 Skill 创建的底部流程操作位置保持一致，不能混入标签 rail，也不能随正文滚走。
- 步骤标签直接使用 `1. 基础配置`、`1. 选择类型`，不另加圆形数字 badge。
- 权限左侧模块 rail 是页面局部导航，不是第二套全局侧栏。桌面内容槽保持左右结构，与 Skill 创建使用同一 `clamp(220px,26%,300px) minmax(0,1fr)` 分栏；左栏展示入口总数、分组名称和分组数量，组间使用轻分隔，当前模块通过整行浅主色底、描边和 `aria-current="page"` 同步表达。
- 模块切换一次点击即更新 rail 选中态和右侧内容，不得出现需要第二次点击才高亮、路由或状态延迟一拍的问题。`1280px` 最小桌面验收仍保持左/右两列、列间距 `16px`、页面横向溢出为 `0`。
- 左栏底部的「本次演示链路」是吸底的当前进度摘要，不是完整审批流水。链路 `<=3` 步时全部展示；超过 `3` 步时默认只展示上一步、当前步和下一步，之前的步骤折成「已完成 N 步 ▾」，之后的步骤折成「还有 N 步 ▾」。折叠行可在原地展开/收起，但列表必须有固定高度上限并在内部滚动，不得继续挤压入口列表。
- 摘要区提供「查看详情」，复用现有申请详情内容区、抽屉或模态工作区展示完整真实链路；没有进行中申请时仅显示「暂无进行中的申请」。折叠计数、当前节点和详情链路必须来自同一申请单数据，不得分别维护 mock。
- 页面内部布局按 `responsive-layout-contract.md` 的分栏和流程规则执行；只改 page-scoped 样式，不污染壳层。

## 7. Skill 创建能力上下文选择器

- 新建默认表单与能力选择为空；只有编辑已有草稿才回填。推荐不等于默认选中。
- 头部固定搜索、业务域、目录和已选标签；底部固定 API/DB/Tool/权限统计；中间能力列表独立滚动。
- 能力卡双列小卡，标题/来源单行省略；选中态使用主色粗描边与轻底，不改变尺寸。
- 能力卡必须提供用途副标题：默认最多两行并以省略号截断；悬停整张卡片或键盘聚焦时，用视口夹紧的 Tooltip 展示完整副标题。Tooltip 只补充被截断内容，不替代卡片内可见信息，也不得被目录滚动容器裁切。
- 能力卡不单独显示未选中圆圈、选中勾选或其他选择图标；默认、Hover、选中分别通过整卡中性描边、轻量 Hover 反馈、主色粗描边与浅主色背景表达，并用 `aria-pressed` 暴露选择语义。
- 强关联能力可在卡片右上角显示小型“推荐”标签，映射必须与当前业务对象绑定；该标签不占独立内容行。推荐与非推荐卡的标题、用途副标题和来源字段保持统一左对齐与统一纵向基线，推荐卡标题为标签预留右侧空间。
- 用户选择或切换菜单后，当前结果中的推荐能力卡必须稳定排列在最前；推荐组与非推荐组内部继续沿用能力目录原顺序。搜索、业务域和“只看已选”仍先过滤再排序，推荐只改变展示顺序，不得自动选中。
- 业务域与已选标签行末尾用下拉展开全部，不使用遮挡文字的浮动左右箭头。
- 已选下拉行按“能力名 / 来源 / 右侧移除”排列，移除按钮垂直居中。
- 使用工作台浅灰细滚动条，不显示系统深色粗滚动条。

## 8. AI 报告与内容槽交接

- 右侧仅展示结论/报告卡；点击展开后通过 Topbar `AI 结果报告`选择器激活对应结果，并在中间内容槽渲染完整长报告，不新开窗口。
- 报告卡保留下载与展开，不显示保存；同一会话可多开报告进行对比。下载只作用于当前报告产物，不改变动态结果的会话归属和关闭逻辑。
- AI 结果打开、切换、返回静态页时内容槽滚到顶部；不改变左导航选中和父级面包屑。
- 报告需保留来源页面、筛选时间、数据口径和生成时间；无权限/脱敏数据不得通过 UI 绕过权限进入 Agent。
- Agent 报告卡在 `1280px` + 默认面板下可纵向滚动，不遮挡 Composer。

## 9. Tooltip 与面板折叠图标

- icon-only 控件必须有 `aria-label` 和 body 层 fixed Tooltip；推荐延迟约 `80ms`。
- Tooltip 视口夹紧并可上下翻转；白底、细边框、轻阴影、`8px` 圆角、`12px/18px` 文案。
- 左侧栏与右 Agent 使用简单面板轮廓图标；左侧展开/收起态镜像内部竖线，右 Agent 使用右侧面板语义。
- 稳定 SVG：`24x24` frame；外框 `x=5 y=4 w=14 h=16 rx=3`、`1.8px` stroke；内部用圆角矩形 `y=6.3 w=1.8 h=11.4 rx=.9`，右线 `x=13.6`、左线 `x=8.6`。不得使用短 LINE。
- 只改变明确请求的 affordance；不改变按钮位置/尺寸、壳层宽度、Topbar、Agent 或 Composer。

## 10. 交互验收

至少验证：

- `1280/1320/1479/1480/1600/1920px` 与 Agent 关/默认/最大组合；记录真实内容槽宽度。
