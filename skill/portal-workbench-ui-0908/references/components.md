# 组件规范（PC 端 · 乐享 AI 工作台）

当前乐享 AI 工作台里反复出现的组件，统一在这里定义结构、状态、用法。生成页面时优先复用这些，
不临时造样式。视觉细节自动继承 `design-tokens.md`（颜色、字号、圆角、控件高度均走变量）。

通用业务内容槽中的组件组合、状态、响应式和交互边界以 `content-slot-design-contract.md` 为权威入口；本文件补充组件视觉与变体细节。
中间内容槽页面样式组件的 A/B/C 成熟度、复用范围和当前登记以 `content-slot-component-library.md` 与 `content-slot-component-registry.json` 为准。本文件不再用章节编号代替组件成熟度。

## 目录

- A. 基础交互
- B. 数据展示

**标记**：⊳ 推荐默认（直接可用，可调）；⬅ 需团队决策。

## A. 基础交互

### 1. 按钮 Button

层级（一个页面主按钮通常只出现一次）：
- **主按钮 primary**：`--color-primary`(#3370FF) 实底 + 白字。页面主操作。
- **次按钮 secondary**：白底 + `--color-border` 描边 + `--color-text`。取消、返回。
- **文字按钮 ghost**：无底无框 + 主色文字。弱操作（更多、查看）。
- **危险按钮 danger**：`--color-danger` 实底或描边。删除、停止等破坏性操作。

尺寸：`sm` 28px / `md` 36px（默认）/ `lg` 44px，对应 `--control-height-*`。
状态：默认 / hover / 按下 / 禁用(opacity .5) / **加载中**（左侧转圈 + 文字"处理中"，禁止重复点击）。

⊳ 推荐：图标按钮（仅图标，方形）用于表格行操作、工具栏，配 tooltip 说明。
⊳ 推荐：主按钮不强制带图标；只有“新建、导入、下载、同步、启动”等动作能被图标快速识别时才加前置图标。默认圆角使用 `--radius-md`（8px），不要把后台主按钮做成胶囊。
⊳ 推荐：附件、发送、刷新、关闭等高频工具操作优先用 icon-only 方形按钮；tooltip 必须在真实页面布局中完整可见，不被顶栏、侧栏、AI 面板、抽屉或输入区裁切。亮/暗切换入口本期隐藏，未来若明确恢复也使用同一 icon-only 规则。

### 2. 输入控件 Form Controls

涵盖：文本框、数字框、下拉单选、下拉多选、搜索框、文本域、复选、单选、开关、日期/时间选择器。

统一规则：
- 标签在输入框**上方**、左对齐（后台密集表单比左右布局更清晰）。
- 控件高度 = `--control-height-md`(36px)，与按钮对齐。
- 焦点态：边框变 `--color-primary` + `--focus-ring`（主色浅底外发光）。
- 错误态：边框 `--color-danger`，下方红字提示，提示说"怎么改"不指责用户。
- 禁用态：底 `--color-bg-muted`，文字 `--color-text-disabled`。
- 占位符用 `--color-text-tertiary`(#7B7B7B)。
- 日期 / 时间输入默认保留系统日历图标和原生可识别性；hover 只允许做轻量可见度增强，不额外叠加蓝底块、白底补片或第二层方形容器。
- 日期范围组件如果使用 `FROM / TO` 双输入或浮层连接角，连接区域必须与整体容器同底色同层级，不能出现明显纯白补丁、割裂接缝或双层外框。

✅ 必填标记：红星 `*`（标签前）+ "(必填)" 文字 并用，双重提示，关键项尤其明确。
✅ 校验时机：**失焦校验为主，提交时兜底**全表再校验一次。实时校验仅用于"密码强度""字数上限"等需即时反馈的少数场景。

### 3. 下拉菜单 Dropdown / 选择器

触发后浮层用 `--shadow-sm` + `--radius-md`，层级 `--z-dropdown`。
选项 hover 用 `--color-bg-subtle`，选中项用 `--color-primary-subtle` 底 + 主色文字。
长列表（>10 项）内置搜索框；多选项显示勾选框 + 已选计数。

## B. 数据展示（当前项目核心）

### 4. 表格 Table —— 后台最重要的组件

结构：
- 表头：`--color-bg-muted`(#F2F2F2) 底 + `--font-weight-medium` + `--text-xs`。
- 行高：普通业务列表默认 `--row-height-default`(48px)；高密度单行表可选 compact 40px，头像/辅助信息可选 comfy 56px，明确主副两行可选 two-line 64px。同一表格不混用行高。
- 行 hover：`--color-bg-subtle`；选中行：`--color-primary-subtle`。
- 斑马纹（可选）：偶数行 `--color-bg-subtle`。
- 单元格内边距 `--space-2`×`--space-3`；数字/ID 列右对齐 + 等宽字体。
- 操作列固定在最右，用图标按钮 + tooltip 或"更多"菜单。

必须考虑的状态：加载中（**骨架屏**优先于转圈）、空数据（见组件 13）、错误重试。

⬅ 决策（按需勾选，影响表头交互）：
- [ ] 列排序  [ ] 列筛选  [ ] 全局搜索  [ ] 批量选择（行首勾选框 + 批量操作条）
- [ ] 列显隐/拖拽排序  [ ] 行展开（展开看详情/子表）  [ ] 密度切换  [ ] 固定列
- [ ] 分页（推荐：底部分页器，支持每页条数切换）

### 5. 指标卡 Stat / Metric Card（仪表盘用）

运营、GEO、GMV、线索等看板常见。结构：标签（次要文字）+ **大数字**（普通 KPI 使用 `--text-2xl`，页面首要 KPI 才使用 `--text-3xl`，均使用等宽栈）+ 同比/环比（升降箭头，升用 success、降用 danger）+ 可选迷你趋势图。
多卡用栅格并排，卡间距固定使用 `--space-kpi-gap`（14px）。

全站中间数据展示区（如运营总览、GEO、在职员工、线索池、数据查询、质量分析）使用统一项目样式：
- 一行 4 张时必须等宽、等高、顶部对齐；使用 `repeat(4, minmax(0, 1fr))` 和 `align-items: stretch`。
- 标准间距：PageHeader 到 KPI grid `16px`，卡片 gap `14px`，KPI grid 到下一模块 `16px`。PageHeader 到首区块的距离与列表、表单、Skill 创建等其他页型一致。
- 页面顶部 KPI、概览指标等主要信息色块使用基于主色 `#3370FF` 推导的四种极浅辅助渐变循环：蓝、青、靛、紫 + 细边框 + 轻阴影；有色辅助色 alpha 必须低于 10%（推荐 2.5%-8%），白色收尾可为 100%，颜色只保留很轻的信息感，不要明显抢眼。下方链路步骤、拆解项、图表容器、表格容器、筛选区、待接口占位块和大面板保持纯白底 + 细边框 + 轻阴影。不要使用语义 wash、普通分类浅红或整排饱和色块。
- 同一 KPI 行不要每张卡都用左侧竖线、顶部粗色条或标签前小圆点点缀。若需要区分类别，优先通过标题、数字层级、分组顺序、辅助文案和图表图例表达。
- 只有页面顶部重点 KPI / 概览指标使用四色浅渐变；卡片内部二级统计块和非主要内容默认白底，避免整页色块过重。该规则必须全站同步，不允许只在某一个模块修正。
- 本地预览若存在模块私有背景色，必须通过共享覆盖层同步到协调多色浅渐变信息底或白色内容容器，不能只改某一页截图里的类名。
- 待接口、空数据、占位数据卡必须与普通数据卡一样使用白底细边框；多个占位卡并排时使用 `--space-kpi-gap`（14px），不允许合并成连续色块。
- 内容顺序固定为 label / value / subtext；数字不拉伸、不变形、不因为单位长短导致卡片错位。
- 推荐分类色：主总量用 primary，正向/已认证用 success，驳回/待处理用 warning，新增长或高级指标用 purple。

### 5.1 ListWorkspace / SummaryList 组合

当列表页同时出现摘要指标、筛选、状态 Tabs、表格和分页时，必须复用该组合，避免组件分别携带外边距：

- `SummaryList = Summary/KPI + ListWorkspace`，二者间距固定 `16px`。
- `ListWorkspace = FilterBar + ListSurface`，二者间距固定 `12px`。
- `ListSurface = Tabs/TableToolbar + DataTable + Pagination`，内部相邻间距为 `0`，通过表面 padding 和 `1px` border 分层。
- PageHeader 到 SummaryList 或 ListWorkspace 固定 `16px`，由 PageHeader/PageFlow 其中一个产生。
- ListWorkspace 及其子项默认 `margin-block:0`；禁止局部页面为“看起来松一点”增加 `margin-top/bottom`。
- 组件按内容自然增高。只有加载骨架、空状态或明确需要页内滚动的超长表格可以设置有理由的最小高度；普通少量数据不得拉伸到视口底部。

### 6. 卡片 / 面板 Card / Panel

白底(`--color-surface`) + `--color-border` 描边 + `--radius-md` + `--space-6` 内边距。
后台默认**靠边框分隔**而非重阴影。可带标题区（标题 + 右侧操作）与底部区。

实现约束：
- 同一 grid 行内的 Card / Panel 必须顶部对齐、等高拉伸；不要用相邻卡片 `margin-top` 制造间距。
- 卡片标题区高度、内边距和右侧操作对齐方式必须统一。
- 模块 / 卡片标题必须固定左上角横排展示，不允许被筛选器或按钮挤成竖排；右侧操作、筛选器、说明文字放不下时换到下一行。
- 标题区采用双边对齐：标题组永远作为左侧锚点，右侧按钮、说明、时间筛选、`问 AI` 等操作贴齐模块右边界；拥挤时只让操作区整组换到下一行左对齐，不压缩标题，不让操作漂浮在中间。
- 标题文字、可选语义图标、标签和右侧按钮必须在同一横向基线或视觉中线上；页面标题不强制使用装饰方块、竖线或圆点。
- 如果沿用已确认模块中的竖线 / 圆点装饰，多行标题时装饰锚定第一行标题文字中线，不跟随整个 header 高度居中。
- 装饰只用于当前页面已有且稳定的层级语言，不能为了统一而给所有新标题批量添加；同级标题的处理应一致。
- 图表卡、表格卡、指标卡混排时，内容区自适应填充卡片；不允许图表在大卡片中显得过小或漂浮。
- 卡片内如果有 Tab、筛选器、按钮组，必须使用独立 header 或 filter row 承载，不要用随意的内联偏移。
- Header 内标题是对齐锚点，filter row 可以换行，不能压缩标题宽度。
- 描边线框型模块在 hover 或 selected 时使用主色描边和轻微主色外环/阴影；不要改成整块高亮背景。页面级 Tab 仍只使用文字色 + 下划线。
- 中间数据区域卡片 / 面板 / 图表卡 / 表格容器 / 链路节点 / 占位卡统一使用轻量 hover：主色浅描边、轻阴影、`translateY(-1px)`、`.14s` 过渡。该效果不作用于 AI 面板、按钮、Tab、表格行和输入框。
- 当前强制浅色主题下，筛选 chip、时间范围按钮、分段按钮必须有足够对比：选中态使用主色底 + 白色文字，未选中态使用当前表面色 + 次级文字，禁用态使用弱边框和弱文字；不要依赖互相冲突的内联色值。未来明确恢复深色时再按同一语义 token 验收。
- 按钮、时间范围 pill、chip、分段按钮和次按钮统一使用 6px 图文间距、8px 同组间距、12px 横向内边距；高度稳定，文本不换行，不能靠临时 margin 或空格制造对齐。

### 6.1 联动筛选型指标卡

当一组指标卡点击后会改变下方列表、图表或表格时，必须明确设计为筛选控件，不要做成普通静态 KPI。

- 结构：`button` / 可点击卡片，包含 `data-method` 或对应筛选值，使用 `aria-pressed` 表示选中状态。
- 外观：白底、细边框、`--radius-md`（8px）圆角、`--space-kpi-gap`（14px）卡片间距；左侧可用极细方法色 accent，但不要整卡强色填充。
- Hover / focus：使用中间数据模块统一轻量 hover；键盘 focus 保留主色 focus ring。
- Selected：主色描边、极浅主色底、右上或标题旁显示 `筛选中` badge；再次点击当前项清除筛选。
- 标题区：如果卡片会联动列表，标题旁给短提示，如 `点击筛选下方员工列表`。
- 联动反馈：被影响的表格 / 列表标题行显示当前条件，如 `当前筛选: 企业邮箱 · 598 条`，并提供 `清除` 操作。
- 典型场景：在职员工管理的 `认证方式分布`。企业邮箱、劳动合同、个人所得税视频认证、其他材料等 tile 点击后必须同步更新下方员工列表。

### 7. 标签 / 徽标 Tag / Badge

状态标签严格按 `design-tokens.md` 第 2 节的状态色：浅底(`*-subtle`) + 实色文字 + 同色小圆点。
计数徽标（红点/数字）用于通知、未读。`--radius-full` 胶囊形。

### 8. 标签页 Tabs

分隔同一页面的多视图。选中态：主色文字 + 主色底部下划线。
适合详情页（概览/日志/配置/版本等多 Tab）。

实现约束：
- 主 Tab 不使用胶囊背景、浅蓝块或按钮底色；只保留字体颜色、底部分割线和选中下划线。筛选 chip / 时间范围按钮才允许使用描边胶囊。
- Tab rail 要预留完整高度和底部分割线；Tab button 高度稳定，计数文字不改变高度。
- Tab 与下方筛选区、表格区之间使用统一间距，不贴边、不重叠。
- Tab 较多时允许横向滚动或自然换行到下一行，不压缩文字到不可读。
- Tab 必须有真实切换逻辑：点击后 active 状态和对应内容面板同步变化；不得只渲染静态 tab 样式。
- Tab 点击交互必须切换标准 `.active` class，并清理冲突的内联颜色 / 下划线样式；不要只改 `style.color` 或 `style.borderBottomColor`，否则会被全站 tab 规范覆盖。

## C. 反馈与浮层

### 9. 弹窗 Modal / 抽屉 Drawer

- 遮罩：`rgba(0,0,0,.45)`，层级 `--z-overlay`。
- 弹窗：居中、`--radius-lg`、`--shadow-lg`、`--z-modal`，宽度 sm 400 / md 560 / lg 720px。
- 必备：标题 + 关闭按钮 + 底部操作区（主/次按钮靠右）。
- 抽屉：从右滑入，宽度 480~640px，适合**较长表单 / 详情**。
- 底部操作区采用内容感知状态：内容能在弹窗可用高度内完整展示时，操作区处于普通文档流，不使用吸底定位和上浮阴影；只有实际滚动容器满足 `scrollHeight > clientHeight` 时，操作区才吸附到底部。
- 吸底后的上浮阴影只表示操作区下方仍有未浏览内容；滚动到内容末尾后移除阴影，保留细分隔线。不得仅根据弹窗类型、字段数量或预设高度强制展示吸底态。
- 弹窗打开、窗口或容器尺寸变化、Tab 切换、校验提示展开、异步内容增减后都要重新判断溢出状态。不要通过固定最小高度制造滚动，也不要让操作区遮挡最后一项内容。

✅ 表单容器规则：简单确认 / 少量字段 → **居中弹窗**；多字段配置 / 详情编辑 → **右侧抽屉**。

### 10. 轻提示 Toast

右上角，`--z-toast`，3 秒自动消失。语义色区分：成功(success)/失败(danger)/警告(warning)/信息(info)，
左侧配对应图标。一次只堆叠少量，避免刷屏。

### 11. 警告条 Alert Banner

页面内嵌的提示块（如"配额即将用尽""有 3 个任务失败"）。浅底(`*-subtle`) + 左侧色条/图标 + 文字 + 可选操作链接。

### 12. 气泡确认 / Tooltip / Popover

- Tooltip：图标按钮、截断文字的悬停说明，深底白字小浮层。
- Popover：点击触发的轻浮层（筛选面板、列设置）。
- 删除等危险操作用气泡二次确认（"确定删除？"+ 危险按钮）。
- Tooltip 展开方向要按位置处理：顶栏和面板头部优先向下，页面底部输入区/页脚优先向上；层级高于卡片、抽屉、AI 面板和 Popover，避免 hover 后被边界截断。
- 下拉小窗、日期时间选择器、筛选 Popover 使用统一圆角、阴影、边框和选中态；不要出现与主系统风格脱节的原生控件样式。

### 13. 空状态 Empty

居中：图标/插画 + 一句说明（为什么空）+ 一个引导操作按钮。
例："还没有模型，点击『创建模型』开始"。

### 14. 加载 Loading

- 表格/卡片：**骨架屏**（灰块占位）优先，体验比转圈高级。
- 局部操作：按钮内联转圈。
- 整页：顶部细进度条 + 内容骨架。

### 14.1 会话状态卡 Conversation State

AI 助手和 Skill 创建 / 需求澄清必须使用统一会话状态组件表达 AI 工作过程。

结构：
- 外层：紧凑过程区；运行过程独立显示，正式答案使用 assistant 气泡，条件性结构输出位于答案之后。
- 单条：图标 24px、标题、状态标签、可选说明、运行中三点动效。
- 状态类型：`thinking`、`tool_call`、`tool_result`、`follow_up`、`confirm`、`streaming`、`error`。
- 状态文案：`等待中`、`进行中`、`已完成`、`失败`、`待确认`。

视觉：
- 默认浅蓝 / 浅灰底，细边框，8px 圆角。
- 已完成用浅成功底，待确认用浅黄底，失败用浅红底。
- 不展示真实思维链，只展示可审计的产品步骤。
- 运行中只允许轻量三点动效，不使用大面积 loading 或遮罩。

### 14.1.1 Agent 结构化执行状态

研发 UAT / POC 接入 Agent 能力时，右侧 AI 助手必须补齐以下结构化状态；不同信息按语义放置，不能全部塞进同一个 assistant 气泡：
- TODO 列表：位于正式答案之后，作为独立直接列表内容；标题、完成数/总数、逐项 `done / running / pending` 状态使用小圆点或勾选态，不加外层气泡、卡片、边框或背景，完成后自动收起。
- 多步骤同时进行：会话状态列表允许多条 `running` 并存，顶部显示轻量汇总，例如 `2 步进行中 · 2 步等待`；不展示真实思维链。
- 授权操作：作为答案后的条件性结构块，展示命名空间、命令/参数、影响说明，以及明确的批准/拒绝按钮；未批准前不得伪装为已执行，结果回到同一回答上下文。

这些状态只扩展消息内容区，不改变 `.ai-panel-header`、Agent composer、快捷标签、队列、面板宽度或壳层裁切顺序。

当前封板范围：
- 右侧 Agent：`AgentMessageList.vue` + `AgentConversationStates.vue`。
- Skill 创建需求澄清：`AgentSkillCreateView.vue` 的澄清对话区。
- 两处都必须支持 TODO List、多步骤同时进行、授权确认卡；遵循“过程区 → 答案气泡 → 条件性结构输出”的信息层级，样式需保持局部作用域，不新增全局 CSS import，不在批准前真实执行命令。

### 14.2 Skill 需求澄清输入区

需求澄清页底部是一个组合输入组件，不是普通表单 textarea。

结构顺序固定：
1. 辅助动作标签行：生成测试用例、检查权限与依赖、运行预览、优化逻辑、风险评估、发布建议。
2. 紧凑输入行：附件按钮、textarea、发送按钮。
3. 流程操作行：上一步、下一步。

规则：
- 辅助动作标签必须在输入框上方，并跟随输入组件；不要移到流程按钮区。
- 标签行单行横向滚动，不允许换行撑高底部。
- 附件按钮、textarea、发送按钮高度一致，0702 基准为 `38px`。
- textarea 默认单行紧凑，不允许用户拖拽改变高度。
- 流程操作行单独展示；`下一步：生成 Skill 草稿` 是主按钮，必须明显、单行、不被输入框或标签挤压。

- AI 结果报告入口位于 Topbar 静态页签右侧，使用单一选择器承载当前会话结果，不再额外占用第二行。未选中时完整显示 `AI 结果报告`；选中后显示约 10 个中文字符的报告标题并高亮。下拉只列出当前 Agent 会话且与具体 assistant 消息绑定的报告，支持切换、关闭、保存态与最多 10 个结果。
- 推荐问题卡片普通字重，使用 `58px` 最小高度，卡片间距保持当前封板的 `10px`；这两个值属于 Agent 专项，不进入内容槽通用间距闭集。
- 快捷/项目标签放在底部输入区上方并与输入框共用一个圆角边框组合件，标签条在上、输入行在下，中间 0.5px 分割线。

- 标签条默认无选中项，只有用户点击 / Enter / Space 激活后才高亮。查询类标签发送对应 query；功能类标签打开对应弹窗、抽屉或页面入口。
- 标签条始终为单行横向滚动 pill，左右两端保留 `24px` 圆形箭头；支持箭头点击、鼠标拖动、触控板横向滑动和键盘方向键。默认、收起、展开、窄屏和 resize 后都保持箭头 + pill 形态，不退化为下拉选择器。箭头在无可滚动方向时 disabled，但不要隐藏到布局消失。
- 输入区：附件 icon-only 方形按钮 + 自增高 textarea + 蓝色发送 icon-only 方形按钮。外层组合件和标签 rail 使用 `--color-surface-subtle`，可编辑输入行使用白色 `--color-surface`，textarea 保持透明并继承输入行白底；placeholder 使用 `--color-text-tertiary`，附件图标使用 `--color-text-secondary`。textarea 默认 `36px`，输入增多时平滑增高，到 3 行约 `75-76px` 后固定高度并出现内部滚动条；空输入恢复默认高度，光标和滚动位置保持在最后一行。Enter 发送，Shift+Enter 换行。
- 输入行默认、hover 和回答中可编辑态均不得使用 disabled 灰底；聚焦时只由外层组合件显示主色描边和 `--focus-ring`，不要新增第二层输入框边框。
- 发送按钮几何不随主题能力变化：`32x32px`、`10px` 圆角、`15px` 单个线性 SVG；当前浅色发布中，禁用态为灰底弱图标，非空发送态为主蓝按钮。若按钮 DOM 已含 SVG，禁止再用 `::before` 生成第二个发送 icon。
- 反例：不要把底部做成截图式的强分隔线框输入组件，不要让发送按钮像独立灰色补丁贴在输入框右侧，不要让 hint 与输入框之间形成第三个边框层级。
- Agent 回答中输入框保持可输入；再次发送进入队列，队列在输入框上方独立展示。输入为空且 Agent 正在回答时，发送按钮切换为停止按钮。
- Agent 等待回答态只是一行透明状态提示：状态点 + 文案 + 三点动效。不得使用 assistant 气泡背景、边框、圆角或阴影。
- 附件、发送、刷新、关闭等 tooltip 必须完整可见，不被容器裁切。亮/暗切换入口本期不展示。
- Agent 面板关闭态必须真正退出可交互区域：面板宽度和 flex-basis 为 0，隐藏态不接收鼠标事件；打开态恢复默认 `380px` 宽度。

### 25. Skill Hub 表格与弹窗（封板业务模块）

用于管理 Skill 生命周期、审批和发布。

结构：
- 摘要卡：状态计数，白底细边框，数字使用 `--text-2xl`（24px），说明使用 `--text-xs`（12px）。
- 筛选栏：搜索输入 + 状态/分类/标签下拉 + 重置按钮，控件高度 36px。

规则：

- 表格 hover 只用浅主色或浅灰，不让整行强色高亮。
- 弹窗遮罩使用 `rgba(31,35,41,.45)` 附近的中性遮罩；弹窗本体白底、细边框、12px 左右圆角。
- 历史旧版 增强：表格行可出现 `应用` 测试入口；点击后只把能力带入 AI 助手说明参数、风险和确认步骤，不直接执行写入。

### 26. 技能包管理弹窗（封板业务模块）

面向业务用户查看、启停、使用、申请技能包。

结构：
- 摘要卡：可用、可申请、待审批、禁用/配置状态计数。
- 工具栏：状态 tabs、`申请技能包` 主按钮、搜索输入。
- 技能包卡片：三列网格；卡片头部为 `语义 icon + 标题 + 状态` 横向居中对齐，右侧更多操作保持同一中心线。
- 启停开关：固定 `76x34`，关闭态灰底，开启态 success 语义底；文本为 `开/关` 或等价短词，不占用两行。
- 批量申请面板：包选择卡片、全选/清空、业务审批人分组下拉、系统审批人只读展示、申请理由和底部操作。

规则：
- 每个技能包 icon 按技能语义设计，不复用同一个图标；但必须同一套线性 SVG 语言。
- icon 容器固定 `34px`，图标 `18px`，主色浅底，标题与状态 badge 同行居中，不允许状态掉到第二行。
- 状态 badge 使用浅底 + 实色文字 + 同色小圆点，颜色语义全站一致。
- 批量申请卡片选中态使用主色浅底、主色边框和自绘 check，不使用原生复选框外露样式。未选中卡片保持白底细边框。
- 审批人下拉是工作台 Popover：白底、细边框、8px 圆角、轻阴影、36px 行高；分组标题使用浅灰底小标题。当前按强制浅色验收，未来恢复深色时跟随语义 token。
- 不要使用 `:has()` 作为唯一选中样式来源；如果项目需要兼容更多浏览器，应同步 class 状态或提供 fallback。

### 27. 工作区静态页签与 AI 结果报告（壳层专项）

用于区分左侧导航页面和 AI 产生的报告/链接/HTML 预览。

结构：
- 面包屑区承载静态页签：业务域文本 + 多个静态页签。
- Topbar 静态页签右侧放置单一 AI 结果选择器；报告、链接和 HTML 预览仍渲染在中间内容槽。
- 报告页包含正常 page header、浅色报告摘要、指标卡、目录和正文。
- 外链页签包含链接标题、来源页、原始 URL code 区和 `复制链接`。
- HTML 预览结果包含 iframe 预览壳，右上保留保存 / 下载 / `关闭`；报告、外链和 HTML 预览的页头退出按钮统一使用 `关闭`，不得显示“返回页面”。

规则：
- 不使用新窗口打开报告、外链或 HTML 预览。
- 下载报告默认 Markdown；HTML 预览下载 `.html`。
- 静态页签和当前会话 AI 结果各自最多 10 个；超过上限自动关闭最早打开的同类结果，并给轻提示。
- AI 结果可保存、关闭、多开，但必须按 `conversationId + messageId` 归属当前会话；关闭最后一个结果后返回当前静态页面。
- AI 结果是动态页签对象，选择器是其展示入口，选中后的结果页是中间内容槽页面。每个结果必须选择 T1–T7 主类型并叠加 V3，优先复用 `ContentPageHeader`、`SectionHeader`、`SectionCard` 及按任务需要的指标、图表、Tabs、表格和反馈组件。
- 动态页签生命周期不得写进 Common 内容组件；禁止 `isAiReport`、`isDynamicTab` 等业务开关，也不得维护另一套 AI 报告按钮、卡片、表格或状态视觉。
- iframe 周围壳层跟随工作台 token，iframe 内部可保持白底以保证预览真实。

## G. 文案呈现约定（UI 相关）

仅收录与"界面如何呈现文字"直接相关的部分；完整的文案口吻、术语表、措辞规范属于
内容/产品写作范畴，不在本 UI 规范内。

### 微文案样式
- **占位符 placeholder**：给示例而非重复标签（如搜索框写"搜索模型名称或 ID"），用 `--color-text-tertiary`(#7B7B7B)。
- **帮助文字 helper**：复杂字段下方一句说明，`--text-xs` + 次要色 `--color-text-secondary`。
- **错误文字**：控件下方，`--text-xs` + `--color-danger`，紧跟出错控件。

### 提示语的视觉结构（呼应组件 11/13/14）
- 空状态：图标/插画 + 一句说明 + 一个引导操作按钮，居中。
- 错误提示：面向"用户能做什么"；技术细节（堆栈、错误码）折叠进"详情"，不顶在界面上。
- 成功/失败反馈：Toast 右上角 + 语义色图标。

### 文字排版细节
- 中英文之间留一个空格，提升可读性。
- 中文用全角标点。
- 英文专有名词保持官方写法：GPU、API、JSON、Token、URL 等。

### 数据显示格式（呈现层）
- **ID / 密钥 / 哈希**：等宽字体 `--font-mono` + 可复制 + 过长截断（中间省略）。
- **大数字**：千分位显示 `1,280,500`（token/调用量等）。
- **日期时间**：`2026-06-03 14:30`（24 小时制）；列表里可用相对时间"3 分钟前"。
- **百分比 / 时长**：`85%` / `12 分钟`，用于配额、进度、任务耗时。
