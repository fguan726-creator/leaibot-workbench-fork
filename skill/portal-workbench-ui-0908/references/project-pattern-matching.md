# 原项目模式匹配规则

本文件用于在新增 PRD 需求实现前，寻找当前联想门户工作台项目中最接近的页面、组件、交互和样式，确保新增页面是旧风格扩展，而不是新视觉系统。

## 搜索顺序

1. 搜索目标功能所在模块附近代码。
2. 搜索同类业务页面，例如管理列表、详情页、审核页、配置页、看板页。
3. 搜索共享组件、CSS 变量、通用 class 和已有交互函数。
4. 搜索 `workbench.css`、`workbench-ui-polish.css`、`workbench-preview-overrides.css` 中的现行样式。
5. 再读取本 skill 的专项 reference。

## 匹配维度

判断相似页面时，按以下优先级：

1. 业务流程相似：用户完成任务的步骤最接近。
2. 页面类型相似：列表、详情、表单、看板、权限、日志等页型一致。
3. 组件组合相似：筛选、表格、Tabs、抽屉、弹窗、图表、AI 面板组合接近。
4. 数据密度相似：字段数量、表格列数、操作频率、页面信息量接近。
5. 状态复杂度相似：审批、异常、权限、批量、失败恢复等复杂度接近。

## 复用要求

复用原项目时优先保留：

- App Shell：左侧导航、顶部栏、中间内容槽、右侧 AI 助手。
- 页头：标题、说明、面包屑、主操作位置。
- 筛选：字段高度、间距、按钮位置、日期范围、折叠方式。
- 表格：行高、列密度、状态标签、行内操作、分页、空状态。
- 详情：头部摘要、Tabs、信息分组、活动时间线。
- 表单：字段分组、校验、底部操作、抽屉/弹窗尺寸。
- 反馈：Toast、确认弹窗、错误提示、加载骨架。
- AI：问 AI 按钮、结论卡、Topbar AI 结果选择器、中间内容槽报告视图。

## 差异处理

- 如果 PRD 字段多于原页面，先扩展既有结构，不改变整体页型。
- 如果 PRD 操作多于原页面，优先收纳到更多菜单、批量操作区或详情操作区。
- 如果 PRD 需要跨对象查看，优先使用 Tabs、抽屉或对象选择弹窗，不新增独立复杂导航。
- 如果 PRD 需要长篇 AI 报告，右侧 AI 面板只放结论卡；完整内容通过 Topbar 单一 AI 结果选择器激活并进入中间内容槽，不创建第二排动态页签。
- 如果旧页面交互确实不足，进入 `reusable-interaction-rules.md` 判断是否新增交互。

## 禁止事项

- 不要因为 PRD 是新功能就新建一套导航、卡片、按钮、状态标签或表格样式。
- 不要把管理列表做成营销式卡片页。
- 不要使用外部组件库默认样式替代项目现有样式。
- 不要为单个字段或单个按钮新增无法复用的页面专属 CSS。
- 不要为了视觉新鲜感改变原项目密度、间距和操作习惯。
