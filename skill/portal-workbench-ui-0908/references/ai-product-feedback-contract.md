# AI改图与AI插图：错误与反馈设计规范

更新：2026-09-08。适用于AI商品管理中改图、插图的五步流程及关联草稿、上传、校验、审批和发布反馈。其他业务页面遵守通用组件规范，不自动继承本文件的物料数量或图片规则。

这是0904统一Skill的反馈设计补充，供PM、UI、研发和验收共用。它定义目标行为，不证明项目已完成改造。只更新本规范不授权修改产品业务逻辑或接入真实服务。

## 1. 使用与依据

- 阅读位置和层级：第2–3节；状态和视觉：第4–5节；触发和逐步场景：第6–7节；生命周期和聚焦：第8–9节；文案与无障碍：第10–11节；实现与验收：第12–13节。
- 基础规则继承[文案规范](content-guidelines.md)、[组件规范](components.md)和[交互规则](reusable-interaction-rules.md)。本文件补齐AI改图／插图的归属和状态处理。
- 下文规则作为这两个流程的目标验收要求。涉及“当前0904实现”的说明是基线观察，实施前复核目标项目的`src/views/ai-product/`与`src/services/aiProductFiles.ts`；不得将本地演示当成真实商品、权限或发布服务验证。
- 本地插图仅确认物料范围时不得宣称真实物料业务校验通过；补齐真实校验属于功能范围，按实际任务授权处理。
- 维护时只在本引用中更新详细场景；主入口和通用文档只保留路由，避免多份规则分叉。

## 2. 核心原则

**用户需要在哪里处理问题，提示就放在哪里。是否阻止下一步，不决定提示在上面还是下面。**

1. 优先关联具体输入、物料、文件或操作，不把所有错误送到步骤顶部。
2. “下面”指紧跟相关对象，不是统一堆放在页面或步骤最底部。
3. “上面”分为步骤顶部和页面顶部，二者不能混用。
4. 每个错误必须说明问题、影响，以及可执行的恢复动作；简单字段错误允许合并为一句话。
5. 用户未执行操作前，空输入和空上传区是初始状态，不提前报错。
6. 错误、待处理、处理中、成功和业务驳回必须准确区分。
7. 同一问题只保留一个主要提示；批量汇总与逐项原因可以同时存在，但不能重复整段文案。
8. 错误提示不得自动清除用户输入、有效图片或已保存成果。

## 3. 提示位置：五个层级

| 层级 | 使用条件 | 固定位置 | 示例 | 处理方式 |
|---|---|---|---|---|
| 字段级 | 修改单个输入即可解决 | 控件下方，先于普通帮助说明 | 未填物料号、重复物料号、无效发布时间 | 字段红框＋错误文字；定位该字段 |
| 对象级 | 问题明确属于某条物料或某张图片 | 物料行的失败原因列；图片卡片的状态／说明区 | 某物料无权限、某图尺寸错误 | 明确对象名称、实际值、要求和处理入口 |
| 区域级 | 一组对象或一次区域操作失败 | 上传框下方；校验按钮附近；结果列表紧上方 | ZIP读取失败、图片数量不足、批量校验失败 | 内嵌Alert；必要时附明细 |
| 步骤级 | 当前步骤整体受阻，无法通过单个字段或区域解决 | 步骤卡片内，“当前配置”下方、首个业务区之前 | 前置配置失效、需要返回物料步骤重新确认 | 提供“返回基础信息／返回物料信息”等明确动作 |
| 页面／任务级 | 整个任务已不可用或所有步骤共同受影响 | 页面标题下方、步骤条之前 | 任务失效、任务权限被撤销 | 一条页面Alert；阻止受影响操作，保留可查看内容 |

### 3.1 位置决策顺序

按以下顺序判断，命中即停止：

1. 整个任务是否不可用？是：页面／任务级。
2. 是否明确属于一个字段？是：字段级。
3. 是否明确属于一条物料或一张图片？是：对象级。
4. 是否属于本步骤的某个上传、校验或审批区域？是：区域级。
5. 是否需要回到前序步骤，或处理本步骤整体前提？是：步骤级。
6. 原因暂未分类？先关联发生失败的操作区域，并使用中性恢复文案；不得把未知异常认定为用户输入错误。

### 3.2 易混淆边界

- “未填写物料号”阻止下一步，但仍放输入框下方。
- “请先校验物料”阻止下一步，但仍放校验按钮附近。
- “需要上传1张，当前0张”放上传框下方，不放步骤顶部。
- “物料范围已变化”在物料步骤内出现时放校验区域；在后续步骤出现时放步骤顶部，并引导返回物料信息。
- 某物料无权限放物料行；整个任务无权限才放页面顶部。
- ZIP解析模块不可用仅影响上传时，放上传区；不是页面级错误，也不是图片不合格。
- 审批／发布操作失败，若可以在当前操作区重试，提示留在该区域。只有任务本身失效才升级到页面级。
- 字段错误很多也不自动升级为页面错误。提交时定位首错，其他字段同时标记即可。

## 4. 严重程度与组件

位置由问题归属决定，颜色和组件由状态语义决定。

| 状态 | 使用情形 | 展示 | 是否持续 | 流程影响 |
|---|---|---|---|---|
| 信息 info | 规则说明、恢复草稿说明、尚未执行校验 | 普通帮助文案或蓝色Alert | 随上下文保留 | 本身不代表失败 |
| 警告 warning | 配置变化导致已有校验失效、存在需确认的后续影响 | 黄色Alert／待重新校验状态 | 直到用户处理 | 如规则要求，仍可阻止后续操作 |
| 错误 danger | 校验明确失败、操作失败；尝试继续时缺少必需前提 | 字段错误、红色Alert或对象失败状态 | 直到修复或相关上下文被替换 | 阻止受影响操作 |
| 成功 success | 当前版本的数据已校验通过、操作明确成功 | 区域成功状态或短暂Toast | 校验结果保留至输入变化；Toast短暂显示 | 仅解锁实际完成的前提 |
| 处理中 loading | 读取ZIP、校验物料、提交审批、发布 | 对应按钮loading＋必要进度文字 | 操作期间 | 防重复请求 |
| 业务状态 | 待审批、审批中、已驳回、待生效、部分成功 | 状态标签／审批记录／结果表 | 持续保留 | 按业务规则开放后续动作 |

补充要求：

- 初始“尚未校验”用中性状态，不提前使用红色阻断提示。
- 用户点击下一步后若尚未校验，展示就近阻断提示；仍不得跳转。
- 审批驳回是业务结果，应保留驳回原因和审批记录，不简化为“系统错误”。
- 持续阻断问题不得只用3秒Toast承载。
- 已在区域展示的失败不得再弹一条相同Toast。
- 保存草稿成功、复制成功等轻量操作可以使用Toast，默认3秒。

## 5. 布局与视觉规范

### 5.1 字段错误

- 使用现有FormField或等效字段结构，不另外插入整行大Alert。
- 控件边框使用`--color-danger`，文字使用`--text-xs`和`--color-danger`。
- 错误文字位于控件下方，间距4px；长度随容器自然换行，不截断关键原因。
- 标签、必填标识保持原位；输入值不清空。
- 帮助文案与错误文案重复时暂时隐藏重复说明；独立的格式规则可以保留。
- 联合字段错误放在字段组下方，例如“日期＋时间”，并关联对应字段。

### 5.2 Alert

- 复用项目语义色及`*-subtle`浅底，不新增页面专用色值。
- 复用TaskNotice／共享Alert基线：内边距12px 16px，圆角`--radius-md`，正文`--text-sm`，行高约1.65。
- 多行提示提供简短标题；标题与正文间距4px。简单一句话无需强行加标题。
- 用语义图标或色条加强识别；不得只依赖颜色表达失败。
- 与所属区域的间距统一为8px；若已有布局容器控制间距，由单一容器负责，避免叠加margin。
- 操作链接放在文案之后，窄宽度时换行；不要挤压文字或固定Alert高度。
- 阻断Alert不提供直接关闭按钮；修复问题后自动移除。

### 5.3 区域顺序

物料区域：录入方式 → 标签／输入框 → 字段错误 → 帮助说明 → 数量与校验操作 → 区域提示 → 校验结果。

上传区域：上传框 → 本次上传操作错误／数量错误 → 图片列表标题 → 批量问题汇总（如需要） → 图片卡片或失败明细。

步骤级：步骤标题 → 当前配置 → 步骤阻断Alert → 业务区域。

任务级：页面标题 → 任务Alert → 步骤条 → 当前步骤。

其中，整个ZIP无法读取时，错误直接跟随上传框；不能隔着空图片列表放到卡片最底部。已解析出具体错误文件时，汇总与失败明细放在图片结果区域。

### 5.4 图片和列表

- 错误对象显示名称、失败原因和处理入口；不能只有一条“校验失败”。
- 拒绝接收的图片可列在失败清单中，不要求加入有效图片预览，但必须保留可识别的文件名。
- “已上传图片”数量只统计当前被接收、保留的图片；失败文件单独计数。
- 图片预览内的移除、替换、重传入口保持可达；没有实现局部重传时，文案仅指向实际存在的上传入口。
- 多种对象失败可以合并在一个列表汇总中，例如“2个物料未通过校验”，逐项原因在行内展示。
- 长文件名允许换行；技术路径和堆栈不直接撑开主区域。

## 6. 校验时机与用户操作

| 时机 | 要求 |
|---|---|
| 首次进入 | 展示规则与空状态，不展示必填错误 |
| 字段失焦 | 校验已交互字段的必填、格式和范围；未访问字段不连带报错 |
| 用户修改已有错误字段 | 可在输入时移除已不适用的旧错误，失焦后重新确定结果；不得每个字符弹提示 |
| 物料输入变化 | 即刻撤销旧“校验通过”，标记“待校验”；本地格式校验不等于物料业务校验 |
| 点击校验 | 先检查必填、重复和数量；通过后才执行业务校验 |
| 选择图片／ZIP | 立即检查格式、大小、结构、命名、尺寸和数量；异步阶段展示loading |
| 点击下一步 | 对当前步骤全检；失败留在当前步骤，定位首个可处理问题 |
| 点击审批／发布 | 复核配置、物料、图片及对应审批前提，不能只依据按钮可见状态 |
| 返回上一步 | 保留输入及仍有效结果；只有依赖数据发生变化才使相应结果失效 |
| 恢复草稿 | 提示哪些内容已恢复、哪些需重新校验；图片不可恢复时明确列出，不能显示为已就绪 |

主按钮规则：

- 普通必填不满足时，允许点击下一步以展示明确错误；不能通过一个没有解释的灰按钮让用户猜原因。
- 校验进行中、提交进行中防止重复触发，按钮显示loading。
- 确定无法执行的权限／审批状态可以禁用主按钮，但必须就近显示原因和下一步动作，不能仅靠Tooltip。
- 客户端校验失败不得发送审批／发布请求；服务端返回业务失败时回写到匹配字段、对象或区域。

## 7. 逐步骤场景矩阵

### 7.1 AI改图

| 步骤 | 场景 | 位置 | 建议文案／动作 |
|---|---|---|---|
| 1 改图基础信息 | 商城、FA、分类、位置未选 | 对应字段下方 | 请选择商城／FA／产品分类／改图位置。 |
| 1 | 当前环境权限校验服务不可用 | 本步骤校验操作区 | 暂时无法校验操作权限，请稍后重试。若服务明确未接入，显示“当前环境暂不支持权限校验”。 |
| 2 物料信息 | 未填、重复、超过20个 | 输入框／导入控件下方 | 请填写至少1个物料号。／存在重复物料号，请移除后重试。／最多20个，当前{n}个。 |
| 2 | Excel无法读取或第一列无物料号 | Excel上传区下方 | 未读取到物料号，请检查首张工作表第一列后重新导入。 |
| 2 | 尚未执行业务校验 | 校验按钮附近 | 请先点击“校验物料”，完成校验后继续。 |
| 2 | 物料不存在、无详情、无权限、商城／FA／分类不匹配 | 物料行；列表汇总 | {n}个物料未通过校验，请处理下方问题后重新校验。逐行展示确切原因。 |
| 3 ZIP下载与回传 | ZIP下载失败 | 下载操作区 | 模板下载失败，请重试。 |
| 3 | ZIP无法读取／空包／未匹配物料文件夹 | 上传区域 | 无法读取ZIP，请检查文件后重新上传。／缺少{物料号}文件夹，请补齐后重新上传。 |
| 3 | 图片格式、大小、尺寸、命名错误 | 对象／失败明细 | 当前尺寸{w}×{h}px，请上传800×800px图片。 |
| 3 | 当前物料范围与上传包不一致 | 上传区域或对应物料行 | 此文件夹不属于本次物料范围，请核对后重新上传。 |
| 4 替换预览 | 本步骤可直接修复的替换图问题 | 图片／物料附近 | 该图片未通过校验，请替换后重新校验。 |
| 4 | 需要回到上传步骤处理缺失文件 | 步骤顶部 | 图片尚未全部通过校验，请返回“ZIP下载与回传”处理。 |
| 4 | 物料／基础配置已失效 | 步骤顶部 | 物料范围已变化，请返回“物料信息”重新校验。 |
| 5 确认并审批 | 审批人未填 | 审批人字段下方 | 请填写审批人，或选择默认审批人。 |
| 5 | 审批提交失败 | 审批操作区 | 审批提交失败，已保留本次配置。请重试。仅在确定未提交成功时提供重试。 |
| 5 | 执行部分失败 | 执行结果区域 | {s}个成功，{f}个失败。请查看失败原因。重试能力需由执行服务支持。 |

### 7.2 AI插图

| 步骤 | 场景 | 位置 | 建议文案／动作 |
|---|---|---|---|
| 1 插图基础信息 | 商城、FA、分类、位置未选 | 字段下方 | 请选择对应配置。 |
| 1 | 橱窗插图数量、坑位错误 | 数量／坑位字段下方 | 插入数量请选择1或2张。／坑位编号请输入1–10的整数。 |
| 1 | 详情顶部与底部合计错误 | 两个数量字段组成的字段组下方 | 顶部与底部合计需为1–10张。 |
| 2 物料信息 | 直接参与物料为空、重复、超过50个 | 物料输入框下方 | 请填写至少1个物料号。／存在重复物料号，请移除后继续。／最多50个，当前{n}个。 |
| 2 | 排除后无参与物料 | 排除物料区域下方 | 排除后没有可参与物料，请调整排除范围。数量必须来自真实范围或明确标注的演示估算。 |
| 2 | 物料不存在等业务失败 | 接入业务校验后：物料明细／区域 | 当前本地实现不校验物料存在性，不得以“物料范围已确认”宣称真实业务校验通过。 |
| 3 配置插图内容 | 点击继续时未上传／张数不足 | 上传框下方 | 本次需上传{expected}张橱窗图，当前{actual}张，请补齐后继续。 |
| 3 | 超数量、同名文件、格式／尺寸／大小错误 | 失败文件明细，必要时批量汇总 | 已存在同名图片，请删除原图后重新上传。／最多{expected}张橱窗图。 |
| 3 | 详情图命名、端宽度、顶部／底部数量错误 | 对应端／区域或失败明细 | PC图片宽度需为1920px，当前{w}px。／{端}{区域}应为{expected}张，当前{actual}张。 |
| 3 | ZIP解析工具加载失败 | 上传框下方 | 暂时无法读取ZIP，请刷新页面后重新上传。提供“查看详情”；刷新前明确未保存内容影响。 |
| 3 | 拖拽跨端或跨顶部／底部 | 对应排序区域 | 仅支持在相同端、相同顶部／底部区域内排序。保留原顺序。 |
| 4 在线审批 | 审批人缺失 | 审批人字段下方 | 请填写审批人，或选择默认审批人。 |
| 4 | 尚未完成当前审批级别 | 审批状态／操作区 | 当前仍在一级审批，完成后才能进入二级审批。 |
| 4 | 审批驳回 | 对应审批节点及原因区 | 显示真实驳回原因和允许的修改／重新提交动作。 |
| 5 确认并发布 | 未完成两级审批 | 步骤顶部 | 请返回“在线审批”，完成两级审批后发布。 |
| 5 | 定时发布日期／时间无效 | 日期时间组下方 | 请选择未来的生效日期与时间。无需顶部重复提示。 |
| 5 | 发布失败 | 发布操作／结果区域 | 发布未完成，请查看原因。按已知结果决定是否允许重试。 |
| 5 | 发布状态未知 | 发布状态区域 | 发布结果暂未确认，正在查询状态。不得直接显示“发布失败，请重试”。 |
| 5 | 部分成功 | 发布结果区域 | {s}个物料成功，{f}个失败。明细区展示对象与原因。 |

### 7.3 图片规则的内容来源

当前0904实现：JPG/JPEG/PNG；缩略／橱窗图800×800px、单张不超过3MB；详情图PC宽1920px、移动端宽750px、单张不超过5MB。

改图详情命名示例：`PC_详情图_01.png`、`移动端_详情图_01.png`。插图详情命名示例：`PC_顶部_01.png`、`移动端_底部_01.png`。

错误文案必须读取当前配置及统一校验规则，不在不同组件内复制一套数量／尺寸常量。详情图需要哪些端，以明确的业务契约为准；本规范不擅自增加“必须同时上传双端”的业务限制。

## 8. 生命周期与状态一致性

### 8.1 出现与消失

- 错误出现：明确校验失败，或用户尝试执行缺少前提的操作时。
- 字段修复：当前错误条件消失后移除该错误；业务校验仍应保持“待校验”，不能直接变成功。
- 对象删除：移除该对象错误，并重新计算数量及区域汇总。
- 重传成功：只移除已解决的文件错误，保留仍未解决的失败项。
- 当前区域重试：按钮loading；提示可显示“正在重新校验”，不得提前宣称成功。
- 切换录入方式：隐藏不属于当前方式的错误；切回时根据保留数据重新判断，不显示另一模式的旧错误。
- 返回步骤：保留仍然相关的结果；跨步骤改变前提后，相关成功状态必须失效。

### 8.2 数据变化与依赖

基础配置改变 → 相关权限／物料校验、图片规则校验及确认状态重新评估。

物料范围改变 → 物料业务校验失效；按物料组织的上传组及确认状态重新评估。

图片增加、删除、替换 → 当前图片规则和数量重新校验；需要重新确认的审批状态按业务规则处理。

只改变顺序 → 保留与顺序无关的格式／大小校验，重新评估坑位与确认状态；不得无理由清空全部素材。

请求发出后输入再次变化 → 旧请求返回的结果不能标记新输入为通过。结果必须关联本次提交的数据版本。

### 8.3 成功反馈

- “物料校验通过”仅用于当前数据版本的全部必要校验成功。
- 仅完成本地格式／范围检查时，使用“物料格式检查通过”或“物料范围已确认”，同时明确业务校验范围。
- “图片校验通过”只在格式、尺寸、命名、数量及配置一致性均满足时显示。
- “合格图片已保留”仅在确实存在保留图片时显示；推荐明确数量：“已保留{n}张合格图片，请重新上传失败文件。”
- 当前保留0张时，改为“本次未读取到可用图片，请重新上传。”

## 9. 多错误与聚焦规则

- 点击下一步后，按页面阅读顺序定位第一个可处理错误；不滚到一个与问题无关的顶部空位置。
- 字段错误：聚焦控件并滚动到可见区域。
- 上传／列表错误：滚动到对应区域，聚焦错误汇总或上传入口；不自动打开文件选择器。
- 步骤／任务错误：聚焦对应Alert；页面跳转后提示跟随目标上下文，不残留在错误步骤。
- 后台校验或失焦校验不强行抢夺用户正在操作的焦点。
- 同一字段优先显示最直接的一个原因；修复后再展示下一条。必填优先于格式，格式优先于业务校验。
- 同一区域多个失败合并为一个汇总，明细可展开；默认最多展示5条，超过时提供“展开全部{n}条”。展开上限为本次目标规则，不是当前已实现能力。
- 字段红字与对象明细可并存；顶部不得再次逐字重复。
- 高层阻断使下游无法校验时，下游显示“待前置条件完成”，不得伪造下游成功或失败。

## 10. 文案规范与示例

### 10.1 文案结构

字段：要求＋修复方式。例：“请输入1–10之间的整数。”

对象：对象＋实际问题＋要求。例：“橱窗图_02.png：当前750×750px，请替换为800×800px图片。”

区域：简短标题＋影响＋动作。例：“ZIP读取失败。本次未读取到图片，请检查压缩包后重新上传。”

步骤：前提变化＋受影响步骤＋明确返回入口。例：“物料范围已变化，请返回‘物料信息’重新校验。”

### 10.2 禁用表述

| 不使用 | 使用 |
|---|---|
| 输入错误／不合法 | 请输入符合具体范围或格式的内容 |
| 操作失败（无后续动作） | 指明失败操作、已知影响和实际可用的恢复动作 |
| 校验失败：Failed to fetch dynamically imported module… | 暂时无法读取ZIP，请刷新页面后重新上传；技术信息放“查看详情” |
| 合格图片已保留（实际0张） | 本次未读取到可用图片，请重新上传 |
| 物料校验通过（实际只确认范围） | 物料范围已确认；说明未进行的业务校验 |
| 发布失败，请重试（结果未知） | 发布结果暂未确认，请先查询状态 |

“查看详情”默认收起，显示便于排查的错误码、请求标识和必要技术信息；不得包含令牌、账号凭据或无关敏感数据。用户主操作不能依赖阅读技术详情。

## 11. 无障碍与响应式

- 字段错误设置`aria-invalid="true"`，通过`aria-describedby`关联可见错误文字。
- 阻断错误用`role="alert"`；普通状态用`role="status"`。批量变化合并播报，不为每个失败图片同时创建一轮高优先级播报。
- 必须有可读的状态文字，不能仅使用红框、红点或颜色区分。
- 错误操作和“查看详情”支持键盘访问，焦点可见；展开后内容进入正常阅读顺序。
- 长错误自然换行；支持Agent展开和内容区变窄，不能产生页面级横向滚动。
- 页面Footer不得遮挡错误和恢复动作。提示出现后若布局溢出，应重新测量滚动区域；不为错误态强制增加整块空白高度。

## 12. 研发共用契约

以下为建议实现契约，字段名可适配项目代码，但职责不可省略。

每条反馈应具备：

- `id`：稳定标识，用于更新、消除与去重。
- `code`：明确错误类型；不得用中文字符串匹配来判断位置。
- `severity`：info／warning／danger／success。
- `scope`：field／item／section／step／task。
- `step`与`target`：所属步骤、字段／区域／对象标识。
- `message`与可选`title`：面向用户的文案。
- `blocking`：受阻的操作，如下一步、校验、审批、发布；不与颜色绑定。
- `action`：实际可执行的重试、返回或定位动作。
- `details`：默认收起的技术信息。
- `revision`：对应输入／配置版本，防止旧校验覆盖新数据。

实现原则：

1. 先把业务错误、文件错误、网络／模块异常分类，再分配展示容器。
2. 组件只负责语义展示，错误归属由业务层提供。
3. 单一错误源派生汇总和明细，不同时写入多个互不关联的提示变量。
4. 上传失败按阶段区分：读取失败、解析失败、文件规则失败、业务关联失败。
5. 不能把`Error.message`原样显示给普通用户；未识别异常使用对应操作区的通用恢复文案。
6. 只有确认操作未生效或服务支持幂等时才允许直接重试审批／发布；结果未知时先查询状态。
7. 不能通过删除错误列表绕过业务校验；页面展示与操作门禁使用同一校验结果。

## 13. 验收清单

每个场景均记录：页面／步骤、输入与配置、触发动作、预期位置、文案、门禁、恢复后状态。两页共用场景均需覆盖。

- [ ] 初次进入空表单没有红色错误。
- [ ] 空物料点击下一步，错误仅出现在输入框下方，页面不跳转，焦点进入输入框。
- [ ] 重复物料、数量超限位置正确；修复后旧错误消失，业务校验不会自动变通过。
- [ ] 改图未校验时点击下一步，错误在校验按钮附近；执行校验后按真实结果更新。
- [ ] 改变物料或配置，旧成功状态立即失效；旧异步请求不能覆盖新输入。
- [ ] 物料单项失败在行内展示，批量汇总计数准确；不得顶部重复同一原因。
- [ ] 未上传或数量不足在上传框下方提示，保留已有有效图片。
- [ ] 错误格式、尺寸、大小、命名均指向具体文件，包含可操作的修复要求。
- [ ] ZIP损坏与ZIP解析模块加载失败使用不同语义，技术原文默认收起。
- [ ] 0张有效图片时不显示“合格图片已保留”；部分成功时数量准确。
- [ ] 图片删除／重传后错误和汇总同步更新，下一步门禁同步变化。
- [ ] 前序配置失效在后续步骤顶部展示，返回入口正确，输入和图片不被无故清空。
- [ ] 审批人缺失和发布时间错误就近展示；没有重复顶部提示或重复Toast。
- [ ] 审批驳回保留业务原因；请求失败与结果未知有明确区分。
- [ ] 整个任务失效才展示页面级提示，并阻止受影响动作。
- [ ] 相同错误连续触发不叠加；重试中不重复提交。
- [ ] 错误文字、图标、边框语义一致，键盘可定位、可操作，读屏有适当反馈。
- [ ] Agent展开、内容区变窄、长文件名和多条错误情况下无页面横向溢出，底部按钮不遮挡内容。
