## 1. 范围与优先级

### 1.1 本合同约束什么

内容槽指顶部导航下方、左侧导航右侧、右侧 Agent 左侧的业务工作区。它包括：

- 页面页头、说明、业务操作区；
- 筛选、搜索、工具栏、批量操作；
- 卡片、指标、图表、表格、列表、分页；
- 详情、表单、配置、任务/导入、分栏设置；
- 动态页签选中后渲染在中间内容槽中的 AI 报告、链接和 HTML 预览结果页；
- 弹窗、抽屉、Toast、确认、空/加载/错误/无权限状态；
- 内容槽内部的滚动、焦点、响应式和跨页状态保持。

### 1.2 本合同不重新定义什么

以下区域继续由原专项规范和当前 Vue 源码约束：

- 顶部导航、静态页签、AI 结果选择器和面包屑；选择器本身不归本合同，但它选中的 AI 结果页面归本合同；
- 左侧导航、折叠按钮和导航信息架构；
- 右侧 Agent、对话状态、Composer、队列、授权卡和 TODO；
- Skill 创建、Skill Hub、权限管理中已有的专属业务流程；
- 品牌、图标、图表、无障碍、Vue 架构等专项合同。

当上述专项页面使用普通筛选、卡片、表格、表单或反馈组件时，组件外观和基础状态仍应遵守本合同；专属流程和壳层行为由专项规范优先。AI 结果的动态页签生命周期由 `workbench-interactions.md` 管理，但结果页本体必须选择 T1–T7 主类型、叠加 V3，并复用内容槽组件库。

### 1.3 冲突优先级

发生冲突时按以下顺序决策：

1. 用户本次明确且经确认的需求；
2. 当前 0825 Vue 项目的可运行行为、数据与不可回退边界；
3. 本内容槽设计合同；
4. 对应专项规范（表格、组件、图表、图标、无障碍等）；
5. Figma 01–03、05 中与当前项目一致的参考；
6. Figma 04 与历史页面，仅作验证证据；
7. 通用设计经验。

不能简单叠加冲突规则。必须记录“采用什么、为什么、影响哪些页面”，再形成一个可执行结论。

## 2. 设计输入与决策方法

新增或优化内容槽页面时，先完成以下判断：

1. 明确角色、任务、业务对象、成功条件、权限与风险。
2. 在当前项目中寻找最接近的已确认页面和组件。
3. 从第 4 节选择一个主页型，必要时只组合一个辅助模式。
4. 列出正常、加载、空、错误、无权限、禁用、提交中、成功等状态。
5. 确定数据规模、字段长度、批量操作、导入导出、异步任务和撤销需求。
6. 在右侧 Agent 打开/关闭、左侧导航展开/收起和窄内容槽下验证布局。
7. 先复用 token、组件与交互；只有既有模式不能承载时才新增模式。

禁止从空白画板直接自由发挥，也禁止只按理想数据设计。至少覆盖长中文、空值、异常值、超大数字、无权限、慢请求和重复提交。

## 3. 内容槽基础骨架

标准页面按以下顺序组织；无对应内容的区域可以省略，但不得任意打乱：

```text
ContentSlot
├─ ContentPageHeader：固定标记 / 唯一 h1 / 描述 / 状态 / 页面级操作
└─ PageFlow：页面区块间距的唯一所有者
   ├─ PageNotice：警告、权限、同步或数据时效说明（可选）
   ├─ Summary：KPI、摘要或任务进度（可选）
   ├─ FilterBar / ListWorkspace：筛选与列表组合（可选）
   ├─ MainContent：表格、图表、表单、详情或工作区
   ├─ Pagination / StickyActions（按页型二选一或省略）
   └─ FeedbackLayer：Toast、Confirm、Modal、Drawer
```

### 3.1 ContentPageHeader

- 每个独立中间内容槽页面的左上角必须放置一个共享 `ContentPageHeader`，并且只能有一个组件实例；其中页面名称是全页唯一的 `h1`。动态报告、详情、创建、设置、WIP 页面同样适用。
- 目标项目中已经验证的共享 `ContentPageHeader` 及其已确认消费者是标题视觉基准。新增页面只通过既有 props/slots 传入标题、描述、状态和操作；不得从截图重新拼标题、复制 legacy `.page-title`，也不得用 page-scoped CSS 覆盖组件标题、标记或操作布局。项目缺少已验证映射时，才按 Skill 资产原样适配。
- 主标题左侧固定使用组件内置的 `18×18px` 项目 icon。icon、主标题、副标题共同构成不可拆分的页头结构；icon 只建立统一视觉识别，不表达业务状态，不允许页面替换为私有方块、竖线、圆点或业务图标。副标题位于 icon/标题行下方，并从组件左边线开始。
- 描述只解释页面目标、数据口径或来源，不重复标题，不承担告警。
- 页面级主操作放右侧，通常最多一个；次操作在其左侧或收进更多菜单。
- 返回、状态、更新时间、数据口径按语义进入独立槽位，不拼进标题字符串。
- 标题和操作在窄宽时允许分行，操作组保持原顺序并避免遮挡。
- 桌面端 PageHeader 使用当前已确认页面的统一节奏：页面标题 `19px/1.35/700`、副标题 `12px/1.65`、标题与副标题间距 `3px`、icon 与标题间距 `8px`；单行标题与副标题时，各页 PageHeader 内容高度由这一排版自然形成，不为专项页面另设固定高度。
- 验收必须在相同 `contentInnerWidth` 下，将新增页与一个已确认的现有消费者并排测量：icon `18×18px`、icon/标题行、标题/副标题排版、操作对齐、页头左边线和首业务块左边线均应一致。任何差异只能作为经确认的共享组件变更处理，不能在单页“微调”。
- PageHeader 到紧随其后的第一个业务区块统一为 `16px`。数据看板 KPI、Skill 创建工作区、表单、列表和专项流程均不得覆盖该距离。
- 页头下间距只能由一种布局机制产生：使用 PageHeader 的 `margin-block-end` 或父容器的 `row-gap` 二选一。禁止二者叠加，也禁止相邻首区块再增加 `margin-top`。
- 页面内部可以存在多个模块标题。Card、KPI 分组、Chart、Table、Filter、步骤区等使用 `SectionHeader` 和 `h2`/`h3` 建立层级，不使用 ContentPageHeader 的固定标记，也不创建第二个 `h1`。
- Modal、Drawer 使用自身标题结构；嵌套 Card 和 Section 标题不使用 ContentPageHeader。

### 3.1.1 SectionHeader 与 SubsectionHeading

- 页面内一级业务模块统一使用共享 `SectionHeader`，标题语义默认是 `h2`。运营总览中的“关键经营链路”“GMV 结构拆解”“核心趋势速览”都属于这一层。
- SectionHeader 固定使用 `4×18px` 主色竖标、`8px` 标题间距和 `16px/1.4/700` 标题；可选 badge、12px 描述、右侧 meta 或 actions。
- 右侧 meta/actions 空间不足时整组换到下一行左对齐，不压缩标题，不把标题或口径排成竖向文字。
- SectionHeader 到模块 Body 固定 `16px`，由模块内部布局产生；不得承担 PageFlow 的页面级间距。
- 模块内部的“分业务”“分平台”等局部分组使用 `SubsectionHeading`：`h3`、`14px/1.4/600`，不带竖标、不带背景。当前只作为样式合同，不单独抽成组件。

### 3.2 PageFlow 与间距所有权

- 每个新增页面必须有且只有一个 PageFlow，负责 PageHeader 之后所有页面级区块的纵向排列。Vue 中可以实现为共享组件或稳定布局 class，但不得省略后再由各区块临时补 margin。
- PageFlow 的直接子项必须声明语义角色：`notice`、`summary`、`filters`、`list-workspace`、`main`、`actions`。子项默认 `margin-block:0`。
- 页面级间距由 PageFlow/SectionFlow 产生；组件内部间距由组件自身的 padding、内部 gap 或 border 产生。任何一条相邻边界只能有一个所有者。
- 内容槽外边距同样只有一个所有者：标准 `20px 24px` 由 Shell `.page-content` 或页面容器二选一提供。若 `.page-content` 的 computed padding 已为 `20px 24px`，路由页面根必须 `padding:0`；禁止再加第二层 `20px 24px`，也禁止用负 margin 抵消。页面根、PageHeader、首业务块应共享同一内容起始线。
- 接入遗留全局样式时，PageFlow/ListWorkspace 直接子项必须归零 `margin-block`，再由唯一的 grid/flex gap 产生间距。尤其不能让全局 `.card { margin-bottom:16px }` 与 PageFlow/ListWorkspace gap 叠加。
- FilterBar、Tabs/TableToolbar、DataTable、Pagination 服务同一数据集时，必须组合为一个 `ListWorkspace`。其中 Tabs/TableToolbar、DataTable 与 Pagination 优先进入同一个 `ListSurface`，用 padding 和分隔线组织，不在它们之间插入画布色空带。
- 标准列表页和带摘要列表页不得使用 `height:calc(100vh - ...)`、`min-height:100%`、`flex:1` 或 grid 拉伸把筛选区、表格卡或 ListSurface 撑满视口。数据较少时，剩余空间属于内容槽画布，不属于列表组件。

统一相邻间距矩阵：

| 相邻区块 | 间距 | 所有者 |
|---|---:|---|
| PageHeader → 首个可见区块 | `16px` | PageHeader 或 PageFlow，二选一 |
| Notice → Summary / Filter / Main | `16px` | PageFlow |
| Summary / KPI → ListWorkspace | `16px` | PageFlow |
| FilterBar → ListSurface | `12px` | ListWorkspace |
| 独立 FilterBar → 独立 MainContent | `16px` | SectionFlow |
| Tabs / TableToolbar → DataTable | `0`，用 `1px` border 分层 | ListSurface |
| DataTable → Pagination | `0`，用 `1px` border 分层 | ListSurface |
| 互相独立的主要业务 Section | `24px` | PageFlow |

禁止用空 div、`<br>`、透明 border、负 margin、固定高度占位或重复 padding 模拟上述间距。响应式换行可以增加区块自身高度，但不能改变区块之间的 token。

标准列表页实现形态：

```css
.content-page-flow {
  display: grid;
  row-gap: 16px;
  min-width: 0;
  padding: 0; /* 外层 .page-content 已拥有 20px 24px 时 */
}
.content-page-flow .card { margin-block: 0; }
.list-workspace { display: grid; row-gap: 12px; min-width: 0; }
```

验收记录至少包含 `.page-content`、页面根、`ContentPageHeader`、首业务块、`FilterBar`、`ListSurface` 的 `getBoundingClientRect()` 与 computed padding/margin。页面根相对内容槽再次内缩 `24px`、页头再次下移 `20px`、或筛选到列表出现 `12px + card margin` 均判定失败。

### 3.3 内容分层

- 画布使用浅灰或已确认的极浅连续渐变；主工作区使用白色 surface。
- 同一层级不要卡片套卡片。需要分组时优先用标题、分隔线和间距。
- 页面主内容默认 `width:100%`、`min-width:0`；阅读/表单型内容才使用窄容器。
- 页面级滚动优先发生在中间内容槽；表格横向滚动只发生在表格容器内。
- 固定底部操作不能遮挡最后一项内容，必须预留等高安全间距。

## 4. 七类基础页型

05 画板沉淀为以下七类基础页型。详情页、日志页、权限页、AI 报告等特殊页型继续由 `page-templates.md` 的专项章节补充。

### 4.1 标准列表页

适用：3 个以内常用筛选、稳定列结构、分页数据。

结构：PageHeader → PageFlow → ListWorkspace（FilterBar → ListSurface〔Tabs / TableToolbar → DataTable → Pagination〕）。存在概览指标时使用 `SummaryList`：PageHeader → Summary → ListWorkspace，不另造组合。

- 搜索在左，筛选居中，查询/重置靠近筛选末端，新增/导出在工具栏右侧。
- 表格是视觉主体，不用大卡片或大面积说明挤占首屏。
- 数据刷新时保留筛选、分页和列宽，避免整页闪白。
- 筛选、状态 Tabs、表格与分页属于同一数据任务时不得成为四个互不关联的 page-level 卡片；优先复用 `ListWorkspace`，以 `12px` 外部组合间距和 ListSurface 内部 `0px + border` 保持连续性。

### 4.2 长筛选列表页

适用：4 个及以上筛选项、跨业务维度查询、需要高级筛选。

结构：PageHeader → PageFlow → ListWorkspace（可展开 FilterBar → 已选条件摘要 → ListSurface〔TableToolbar → DataTable → Pagination〕）。存在 KPI 摘要时与 T1 相同使用 `SummaryList`：PageHeader → Summary → ListWorkspace；KPI 不会把列表页自动改判为 T3。

- 默认展示最高频的一行条件；次要条件进入展开区。
- 展开/收起不能清空已填值；收起后仍需显示隐藏条件数量或条件摘要。
- 四列筛选以“内容槽可用宽度”为判断，不以浏览器 viewport 为判断。宽内容槽可四列，空间不足依次降为两列、一列。
- 日期区间、级联对象选择等宽字段可跨两列，不强行塞入等宽小格。

### 4.3 数据看板页

适用：运营总览、趋势、质量、流量、GMV、GEO 与线索看板。

结构：PageHeader / 全局时间条件 → KPI → 主趋势 → 分布/拆解 → 明细或异常列表。

- KPI 只展示决策必要指标；一般首行 3–4 张，窄宽自动换列。
- 同一指标的口径、时间、单位、颜色在整页保持一致。
- 图表必须有标题、口径/时间、Tooltip、空/错误状态；图例不能代替数据结论。
- 告警使用 Alert，不把红色作为普通分类或大面积图表主色。
- 图表联动筛选必须可撤销，并明确当前已选范围。

### 4.4 业务表单页

适用：新建、编辑、审批信息录入、规则配置。

结构：PageHeader → 分组说明 → Form Sections → StickyActions（长表单）或普通 Actions（短表单）。

- 标签默认在控件上方；必填、帮助、错误分别占稳定位置。
- 字段按用户任务分组，不按数据库字段顺序堆叠。
- 失焦进行字段校验，提交时全表校验并将焦点移到首个错误。
- 离开有未保存变更的页面前必须确认；保存中禁止重复提交。
- 简短、低风险编辑可用弹窗；多字段或需要对照上下文时用右侧抽屉；复杂流程用步骤页。

### 4.5 任务 / 导入页

适用：文件上传、批处理、异步计算、报告生成。

结构：PageHeader → 任务说明/模板下载 → 上传或参数区 → 任务进度 → 结果摘要 → 失败明细/历史记录。

- 上传前说明格式、大小、字段要求与隐私风险；拖拽区必须同时提供按钮入口。
- 解析、校验、排队、运行、部分成功、成功、失败、取消均为独立状态。
- 部分成功必须显示成功/失败数量并允许下载失败明细。
- 长任务允许离开页面，并通过任务列表或通知恢复；不能伪装成同步完成。
- 重试只重试失败项时要明确范围，避免重复处理成功数据。

### 4.6 分栏设置页

适用：模块设置、角色权限编辑、对象选择与详情联动。

结构：PageHeader → 左侧局部导航/对象列表 → 右侧设置工作区 → 当前分区操作。

- 左栏是页面内导航，不复制全局左导航视觉层级。
- 选中项、未保存标记、搜索结果和无权限项需可区分。
- 窄内容槽下左栏可移到上方或切为选择器，但右侧工作区不能居中裁切。
- 切换对象前处理未保存状态；不同配置组独立保存时必须反馈保存范围。

### 4.7 配置列表页

适用：规则、模型、渠道、数据源、Skill 配置等对象管理。

结构：PageHeader → 状态/分类 Tabs → FilterBar → 卡片列表或表格 → Pagination / LoadMore。

- 表格适合字段对比和批量管理；卡片适合少量对象及能力摘要。不得只为“好看”改成卡片。
- 启用/停用、发布/撤回、删除等状态操作必须显示影响范围与结果。
- 草稿、已发布、失败、停用等状态使用统一 StatusTag，不只靠颜色区分。
- 空状态按当前分类解释原因，避免所有 tab 共用一句“暂无数据”。

## 5. 视觉与密度合同

### 5.1 字体与层级

- 字体沿用项目真实栈：`Source Han Sans CN`、`PingFang SC`、`Microsoft YaHei`、system-ui；不要求引入 Chiron Hei HK。
- 页面标题必须使用 `ContentPageHeader` 专项 `19px` 主标题与 `12px` 副标题，不从通用字号阶梯临时取值；区块标题使用 `--text-md`（16px），正文说明使用 `--text-base`（14px），表格/表单/按钮使用 `--text-sm`（13px），辅助信息使用 `--text-xs`（12px）。
- ID、Key、Hash、日志、精确技术数字使用等宽字体；普通中文数字不强制等宽。
- 不用超大标题、营销文案或字体粗细堆叠制造层级。

### 5.2 间距与容器

- 内容槽常用内边距 `20px 24px`；PageHeader 到首个业务区块固定 `--space-4`；其余顶层业务区块使用 `--space-6`，同一区块内模块使用 `--space-4`，普通卡片内边距使用 `--space-5`。紧密图标/文字组使用 `--space-2`，字段或操作组使用 `--space-3`；不得在 8–12px 之间任意取值。
- KPI 组合统一为：页头到 KPI `--space-4`、KPI 卡间 `--space-kpi-gap`、KPI 到下一模块 `--space-4`。页头到首区块的节奏与所有其他页型相同，不再作为看板例外。
- 控件、紧凑卡片和普通数据卡使用 `--radius-md`（8px）；大卡片、弹窗和抽屉使用 `--radius-lg`（12px）。细边框、轻阴影保持不变；不要使用区间内任意圆角，也不要用厚重投影、发光或大面积饱和渐变。
- 长页面中的同类卡片保持相同内边距、标题位置和操作区高度。
- 空间不足先减少列数和辅助信息，不任意缩小字体或控件点击区域。

### 5.3 控件尺寸

- `28px`：紧凑筛选、表格工具栏和表格行内操作。
- `36px`：默认输入、按钮、选择器和普通表单。
- `44px`：仅用于经确认的高强调入口或特殊触控场景，不作为内容槽默认按钮高度。
- 同一操作组保持同高；图标按钮需有 Tooltip 和可访问名称。

### 5.4 表格密度

- compact `40px`：单行、高密度任务/配置表。
- default `48px`：普通业务列表的默认选择。
- comfy `56px`：含头像、标签组合或较多辅助信息。
- two-line `64px`：明确的主副两行内容。
- 同一表格只能选择一种行高变体，不能因单行/双行数据在行间随机跳变。
- 内容溢出按字段语义使用省略、换行、Tooltip、展开或详情，不能靠无限增高行解决。

### 5.5 筛选标签

- 业务表单始终展示可见标签。
- 紧凑筛选中，仅当占位文案和上下文足以唯一说明字段时可以省略外部标签，但仍必须提供程序化可访问名称。
- 同类、重复、风险较高或易混淆字段必须展示标签，例如多个日期、多个状态、多个组织层级。
- 占位文案是输入提示，不代替持久字段名；输入后仍需知道当前条件含义。

## 6. 核心组件合同

### 6.1 FilterBar

- 条件顺序按使用频率和业务逻辑，不按后端字段顺序。
- `查询`应用当前条件；`重置`恢复产品定义的默认条件并立即明确是否重新查询。
- 条件变化是否自动查询必须在同一页面保持一致；昂贵查询默认显式提交。
- 展开高级筛选、清空单项、全部重置、恢复默认值均需有可预测行为。
- 所有 grid/flex 子项 `min-width:0`；禁止为四列布局写页面级刚性最小宽度。

### 6.2 TableToolbar

- 左侧展示总数、选中数量或当前视图；右侧放刷新、列设置、导出、新增等操作。
- 选中行后进入明确的批量模式；批量操作完成、取消或翻页后的选择保留策略必须定义。
- 导出需说明范围：当前页、当前筛选结果或所选项；大数据导出进入异步任务。

### 6.3 DataTable

- 名称左对齐、数字右对齐、状态左对齐、操作固定最右。
- 操作列在横向滚动时保持可达；固定列必须有轻分隔，不能覆盖内容。
- 表头排序、筛选和帮助说明具有清楚的命中区与键盘状态。
- 行点击与行内按钮不能冲突；若整行可点击，仍需提供可识别的主链接或可访问说明。
- 列显隐、列宽、密度等用户偏好如被持久化，需要提供恢复默认。

### 6.4 Pagination

- 放在数据容器底部，显示总量并支持每页条数时说明改变后的定位策略。
- 筛选、排序、切换 tab 后统一回到第 1 页；仅刷新当前页数据时保留当前位置。
- 删除最后一页最后一项后回到有效页，不展示不存在的空页。
- 数据量少可隐藏分页控件，但容器底部节奏保持一致。

### 6.5 Overlay Form

- Modal 用于短任务、确认和低上下文依赖操作；Drawer 用于多字段、需要参照当前页面或较长编辑。
- Modal Footer 默认跟随内容自然排列且无上浮阴影。仅当实际内容区发生纵向溢出时切换为吸底 Footer；内容仍可向下滚动时允许轻量上浮阴影，到达滚动末尾后移除阴影并保留 `1px` 分隔线。
- 溢出状态必须由真实滚动尺寸判断，并在容器 resize、Tab/步骤切换、校验信息和异步内容变化后更新；不得用字段数量、弹窗名称、固定高度或永久 sticky class 代替判断。
- 打开后焦点进入标题或首个可操作控件；关闭后回到触发入口。
- Escape、遮罩点击和右上角关闭是否允许，按风险统一；有未保存内容时必须拦截。
- 提交中保持按钮状态、避免重复点击；失败时保留用户输入。

### 6.6 StatusTag、Alert 与 Toast

- StatusTag 表达对象的持续状态；Alert 表达页面/分区级问题；Toast 表达操作结果。三者不可互相替代。
- 状态不能只靠颜色，必须有文字；同一语义全站使用同一色彩与文案。
- Toast 不承载需要用户阅读或操作的重要错误；严重错误应留在相关区域并提供重试/详情。

### 6.7 Empty、Skeleton 与 Error

- Empty 说明“为什么为空”和“下一步做什么”；搜索无结果与初始无数据使用不同文案。
- Skeleton 应匹配最终结构，避免加载完成后大幅跳动；未知时长不显示虚假百分比。
- Error 保留已有数据时优先局部提示；整页不可用时提供重试、问题范围和必要的追踪信息。

## 7. 交互与反馈合同

### 7.1 状态连续性

- 返回列表时尽量恢复筛选、排序、分页、展开行和滚动位置。
- tab 切换是否保留子状态必须有一致策略；不能一部分保留、一部分静默清空。
- URL 可表达的查询条件优先进入 route query，便于刷新、分享与返回。
- 后台数据变化导致当前对象失效时，明确提示并提供回到有效视图的路径。

### 7.2 风险操作

- 删除、停用、撤回、覆盖、批量变更、权限提升必须说明对象、数量、影响与可恢复性。
- 可撤销的操作优先使用撤销；不可撤销或高影响操作使用二次确认。
- 确认按钮使用具体动词，如“删除 12 条线索”，不用模糊“确定”。
- 权限不足不显示假成功，也不能用禁用按钮替代必要说明。

### 7.3 异步与并发

- 发起请求后给就地反馈；超过短等待阈值显示加载状态，不能只依靠全局 Toast。
- 防止重复提交；对并发更新、版本冲突或数据已变化给出刷新/覆盖/取消选择。
- 轮询任务要显示最后更新时间、当前阶段和停止/重试能力。
- 乐观更新失败时回滚界面并解释受影响对象。

### 7.4 键盘与焦点

- 所有交互可由键盘到达，焦点样式可见且不被 `outline:none` 移除。
- 弹层使用焦点圈定；关闭后焦点返回触发源。
- 表单错误摘要、筛选结果变化、异步完成等重要变化需有屏幕阅读器可感知反馈。
- Tooltip 不作为唯一信息来源，也不能只在 hover 时可见。

## 8. 页面状态与异常场景

每个页面至少检查以下状态：

| 状态 | 必须回答的问题 |
|---|---|
| 初始 | 默认筛选、数据口径和主任务是否清楚 |
| 加载 | 加载范围、是否可取消、旧数据是否保留 |
| 空 | 初始无数据、筛选无结果、无权限是否区分 |
| 错误 | 哪部分失败、是否可重试、输入是否保留 |
| 无权限 | 缺少什么权限、如何申请、可见范围是什么 |
| 禁用 | 为什么不可用、满足什么条件后可用 |
| 提交中 | 是否防重、能否离开、结果如何恢复 |
| 成功 | 哪些对象已改变、下一步和撤销入口是什么 |
| 部分成功 | 成功/失败数量、失败原因和重试范围 |
| 数据过期 | 最后更新时间、刷新策略和冲突处理 |

此外必须验证：0/负数/极大值、超长中文/英文/ID、缺失头像、未知状态、时区、跨天日期、1 条/恰好一页/多页、删除至空页、网络中断和重复点击。

## 9. 响应式与壳层协作

- 具体容器等级、字段最小宽度、七类页型降级矩阵、container query / ResizeObserver 选择和测试尺寸以 `responsive-layout-contract.md` 为权威规则。
- 所有内容槽断点以“内容槽实际可用宽度”为依据，而不是只看 viewport。右侧 Agent 打开会改变可用宽度，必须触发同等布局响应。
- 顺序固定：内容槽内部栅格降列/换行 → 左导航按壳层规则收起 → 右侧 Agent 约束或抽屉化。
- 主列使用 `minmax(0,1fr)`，直接 flex/grid 子项使用 `min-width:0`。
- 筛选在内容槽内宽 `>=1040px` 使用四列，`720–1039px` 使用两列，`<720px` 使用一列；日期范围、级联等宽字段按专项合同跨列。
- `1040/720px` 只固定基础栅格密度，不固定页面或字段像素宽度；页面继续 `width:100%` 流式撑满，四列使用 `minmax(0,1fr)` 自适应。不得另以 `920/620px` 建立平行的通用断点体系。
- 表格宽列允许容器内横向滚动并固定操作列；页面根节点不产生横向滚动。
- 图表在容器 resize、Agent 开关、tab 切换和筛选展开后重新测量。
- 1280px 桌面基线且 Agent 打开时，页面级 `scrollWidth - clientWidth` 应为 0。

## 10. 复用、例外与演进

### 10.1 复用层级

- Common：跨 2 个以上业务域稳定复用，如 PageHeader、FilterBar、DataTable、Pagination、StatusTag、EmptyState。
- Domain：同一业务域复用，如认证审核状态流、线索评分展示。
- Page-local：单页、定义不稳定或高度专属的组合。

不要为了组件数量拆分，也不要把具有不同语义的控件强行统一。共享组件至少稳定复用 2 次；相同交互成功出现 3–5 次后更新专项规范。

### 10.2 允许例外的条件

只有在以下条件同时成立时允许偏离基础合同：

- 业务任务无法由现有页型/组件合理承载；
- 偏离能显著改善效率、可读性或风险控制；
- 已定义完整状态、键盘、响应式和失败回退；
- 记录适用范围，不污染其他页面；
- 经用户或设计负责人确认。

### 10.3 规范演进记录

每次新增稳定模式时记录：问题、采用方案、替代方案、影响页面、迁移成本、回退方式和验收证据。不要把一次性 POC 或 UAT 偏差直接写成全局规范。

## 11. 设计与验收清单

### 设计前

- [ ] 明确内容槽范围，没有重做封板壳层或 Agent。
- [ ] 已选择主页型并找到当前项目相近页面。

### 视觉与结构

- [ ] 页面只有一个清楚的一级标题，主操作通常只有一个。

- [ ] 控件高度、表格行高、间距在同一页面一致。
