# P0 性能维护与验收

本次改动只覆盖 `public/leaip0` 与直接配套构建检查，不修改共享后端、支付接口或本机代理。

## 发布前门槛

在新鲜代码工作区运行：

```sh
node scripts/build-p0-home-assets.cjs --check
node scripts/check-p0-performance.cjs
node scripts/test-p0-lifecycle.cjs
node scripts/check-p0-performance.cjs --origin https://p0.leaibot.cn
```

第一条检查来源文件、内嵌模块、生成包和五频道版本号一致性。修改规范来源后，用 `--stage /绝对路径/新目录` 生成待审产物；脚本不会部署。禁止只改 bundle 或用旧 HTML 覆盖线上。

第二条限制每频道首屏请求数、gzip 字节和内嵌 HTML 大小，检查功能懒加载、缓存版本、脚本语法。预算是当前可用版本的防回退上限，并非“性能已达标”。修改预算需要说明新增需求与收益，不能为通过检查自动抬高。

第三条覆盖 iframe 已完成、跨域事件记录、加载失败、超时和导航改变后的监听清理。

第四条只发 GET，检查五个入口与三个商品系列的 SKU 数据契约。入口必须是 P0 的 Nginx 域名，不能用共享后端的 3031 端口代替静态页面入口。不发送订单、支付、会员、地址或 AI 请求；不启动共享后端、不读写数据库。

GitHub 工作流仅有仓库只读权限；必须合入目标分支后才会按触发条件运行。配置工作流不等于已经运行，更不等于已设置分支保护必过项。参考 [Checkout](https://github.com/actions/checkout) 与 [Setup Node](https://github.com/actions/setup-node)。

## 浏览器回归（不能由静态门槛替代）

- `/`、`/shop-chat/`、`/b-chat/`、`/biz-chat/`、`/brand/`：首屏、导航、输入框、商品详情、关闭/切换页签。
- 个人与中小企业：配置切换、价格和商品名称对应、仅打开下单弹窗，禁止实际支付。
- 会员/订单：首次点击才加载，错误能恢复；品牌与政企保留原功能差异，不强塞个人购物流程。
- 扩展详情返回 503 时，基础名称、价格和全部配置仍可展示；遮罩不会无限等待。
- 在隔离预览中运行 `scripts/fixtures/p0-stream-test.html`（把其中资源路径映射到待发布的 helper），检查节点和事件保留、Markdown 修正、完成/超时/旧页面清理。不得公开诊断页面或绕过鉴权。

## 仍未完成的深层工作

- 首页约 694 KB 的大 CSS、约 600 KB 的主程序依然存在。不能随意按字符串拆分闭包或调换 CSS 顺序；需要逐模块契约和视觉回归后继续拆。
- 目前仍保留旧 HTML 会话持久化格式、部分老业务观察器，以及兼容旧缓存的历史包。
- 公网连接与下载异常尚未归因到单一环节。源站快不代表公网快；本地 SSH 预览结果也不能代替公网浏览器的首屏数据。
- 本轮资源预算不计算图片、iframe、API、动态业务加载总量；HTTP 冒烟测试也不证明真实用户网络速度。

每次上线前保留 P0 全量备份，确认改动文件现场哈希与基线一致，依赖文件先于 HTML 发布；随后记录日志、提交精确文件、推送独立版本分支并释放自己的编辑锁。
