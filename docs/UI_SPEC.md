# 权限系统 POC UI Spec

版本：v2.8
更新日期：2026-09-08
页面范围：登录页、无权限页及权限管理工作台（申请、审批、角色、用户、组织、菜单、数据源）。

## 1. 目标与非目标

- 目标：将账号创建与权限申请合并，让内部用户在无权限错误页内完成首次访问申请，按人员身份生成正确审批链路，并降低申请人和管理员的操作复杂度。
- 目标用户：内部申请人、外部申请人、关联人、直线经理、业务负责人、系统管理员。
- 核心任务：首次访问申请、外部账号创建并授权、权限变更审批、用户权限维护、数据源绑定。
- 非目标：本期不接真实组织架构、SSO、审批引擎或数据源接口；POC 继续使用前端 mock 数据。
- 非目标：不改变既有权限数据、审批状态机、路由和 mock 数据语义；不引入新的生产依赖。

## 2. 视觉与交互依据

优先级如下：

1. 项目内 `skill/portal-workbench-ui-0908/SKILL.md` 为当前默认视觉、交互和响应式规范；0825 与 0818 仅作为历史非回归依据。
2. 本轮评审结论和用户确认的审批规则。
3. 当前 Vue POC 已验证的共享组件、状态逻辑和交互实现。
4. `docs/portal-workbench-permission-design.md` 中的权限分层原则。
5. 全局《Codex 前端 UI 开发协作 STD》。

项目工程仍保留既有设计 Skill guard；权限管理页在本轮明确采用 0825 Skill。若旧页面私有样式与 0825 的内容槽合同冲突，以 0825 的权限专项合同为准，同时保持已验证业务行为不变。

### 2.1 SPEC-12：0825 权限工作台视觉治理

- 页面归类为 `T6 分栏设置 + V2 多步流程 + E3/E4 权限专项`。
- 页面只保留一个 `ContentPageHeader`；各权限模块统一使用共享 `SectionHeader`，不复制私有标题 DOM。
- 左侧 `PermissionModuleRail` 使用 `clamp(220px, 26%, 300px)`，展示总入口数、分组数和当前选中项；选中态同时具备浅主色背景、整行描边和 `aria-current="page"`。
- `1280px` 最低桌面基线及 Agent 展开后的窄内容槽仍保持左右两列，不隐藏 Rail 搜索、分组名称、分组数量或入口文字。
- 页面内部网格按内容槽宽度使用 container query 降级；不得使用 viewport 宽度猜测内容槽列数。
- 共享控件采用 36px 默认高度、8px 圆角、13px 文案和统一 focus ring；数据表表头 40px、默认数据行 48px。
- 页面根不得产生横向溢出；模块列表、审批链路、表格及弹窗在各自边界内滚动。

## 3. 平台与布局

- 高保真目标：PC 管理后台，主要验证 1440×900。
- 最小支持宽度：1024px；小于该宽度以不遮挡、不丢失关键操作为目标。
- 登录页和无权限页继续支持现有移动端防溢出布局。
- 无权限页申请卡片水平居中，表单内容保持左对齐；页面内容超过视口高度时由页面纵向滚动。
- 页面级滚动沿用现有工作台；权限选择弹窗内容超高时由弹窗主体独立滚动，底部操作必须可达。

## 4. 通用交互规则

- 人员类型决定字段和审批节点：外部用户永远不展示“被申请人直线经理”。
- 多个业务负责人必须全部通过，权限才一次性整体生效。
- 申请人最终提交页只展示审批流，不展示复杂权限变更摘要。
- 权限变更摘要只在审批列表或审批详情中展示。
- 启用/禁用申请单号由提交后自动生成，表单中不要求手填。
- 复制权限与手工追加权限分区展示，来源清楚且互不混淆。
- 首次访问页基本信息仅保留自动带出的申请人 ITCode、直线经理，以及选填的手机号、邮箱和申请原因。
- 首次访问、创建账号和权限变更使用同一套权限范围组件、目录数据、状态计算和校验逻辑。三处页面均先展示必填的“所属租户”多选，再依次展示“添加角色”“复制他人角色”“选择数据权限”三个非必选入口；角色统一采用列表与详情双栏、功能/数据页签和分组权限树。手工添加角色时，可在该角色绑定范围内勾选功能权限，勾选功能会自动选中对应角色，不能脱离所选角色新增功能；复制角色的功能权限保持完整且只读。普通数据权限统一采用“业务目录 → 数据源 → 授权项”三级结构，前两层只展开/收起，第三层勾选，默认展开。
- 首次访问、创建账号和权限变更的所属租户均支持多选，并在审批侧完整展示。
- 表单校验在字段附近展示；提交失败不得静默。

## 5. 关键组件状态

| 组件 | 默认状态 | 禁用/只读 | 错误/空状态 |
| --- | --- | --- | --- |
| 无权限错误页 | 居中展示基本信息、权限范围和提交申请三步流程 | ITCode、直线经理自动带出；已有待审批申请时显示原申请结果 | 无 ITCode 时使用安全占位；内容超高时页面可滚动 |
| 权限范围 | 展示角色、复制结果、数据权限三种来源 | 复制结果整体锁定；手工角色功能可在角色范围内勾选 | 无权限时展示明确空态 |
| 审批流 | 按身份动态生成节点 | 已完成节点只读 | 缺审批人时展示“待带出” |
| 审批详情摘要 | 展示新增、移除和来源变化 | 申请信息只读 | 无变化时展示“未检测到变化” |
| 用户编辑 | 基础信息、角色、数据权限统一入口 | 详情模式全部只读 | 保存错误定位到对应页签 |
| 数据源绑定 | 仅选择一级目录/大菜单 | 子菜单不可选 | 未选择一级目录时阻止保存 |

## 6. 禁止项

- 不为外部用户生成直线经理字段或审批节点。
- 不允许修改、删除或局部清除“复制他人角色”带入的任何权限；手工角色功能只能在所选角色绑定范围内勾选，不允许脱离角色直接新增功能权限。
- 不允许业务负责人部分通过时提前生效部分权限。
- 不把系统管理员放在普通权限变更的最终审批节点。
- 不继续保留外部登录页自助创建账号入口。
- 不允许内部首次访问申请从无权限错误页跳转到后台权限管理页面。
- 不允许首次访问页与系统内申请页使用两套不同的权限范围入口或复制权限规则。
- 不在用户列表操作列同时保留“编辑”“设置角色”“分配数据权限”三个入口。

## 7. 技术约束与验证

- 框架：Vue 3、Vue Router、Pinia、TypeScript、Vite。
- 样式：继续使用组件内 scoped CSS 和现有 class，不增加无边界全局覆盖。
- 数据：沿用 localStorage 和页面内 mock 状态，保持邮件 mock 可演示。
- 基础验证：`pnpm run typecheck`、`pnpm run lint`、`pnpm run build`。
- 浏览器验证：按 `docs/UI_ACCEPTANCE.md` 覆盖 1440×900 的主要身份和流程。
## 8. SPEC-06：三场景权限范围统一

详细业务口径以 docs/permission-poc-specs.md 的 SPEC-06 为唯一事实源，本节只记录 UI 与实现边界。

### 8.1 固定结构

权限范围页面从上到下固定为：

1. 标题和说明。
2. “所属租户”多选，标记必填，至少选择 1 项。
3. “添加角色”“复制他人角色”“选择数据权限”三个操作按钮。
4. 按来源分组的已选结果与中性空态。
5. 当前场景的上一步、下一步或最终操作。

三处入口的按钮文案、顺序、弹窗行为、权限目录和结果展示必须一致。视觉以系统内现有权限范围页面为基准；首次访问页只适配外围容器和移动端宽度，不改变权限选择交互。

### 8.2 场景规则

| 场景 | 租户 | 三个权限入口 | 最终提交 |
| --- | --- | --- | --- |
| 首次访问 | 多选、至少 1 项 | 均非必选 | 允许仅选择租户 |
| 权限变更 | 多选、至少 1 项 | 均非必选 | 最终有效权限必须不同于进入流程时的基线 |
| 创建账号 | 多选、至少 1 项 | 均非必选 | 允许仅选择租户 |

权限变更必须比较归一化后的最终租户、角色、角色推导的有效功能权限、有效数据权限及用户级数据例外集合，不能以“是否点击过按钮”判断。仅打开弹窗、改变顺序、重复选择或选择后恢复原状都不算变更。

### 8.3 状态与反馈

- 未选择租户：字段附近展示错误并阻止继续。
- 未添加角色或数据权限：展示中性空态，不报错。
- 无权限变化：只在权限变更最终提交时拦截，错误使用可访问告警语义，返回上一步后保留已填内容。
- 目录加载、搜索无结果和复制失败均提供恢复路径，不清空其他已选内容。
- 弹窗覆盖键盘焦点、Esc、长内容滚动和底部操作可达状态。
- 从“审批列表 → 审批操作 → 完整权限范围”打开添加角色、复制他人角色或选择数据权限时，权限子弹窗必须位于审批弹窗及其遮罩之上；外层审批弹窗保留在背景，子弹窗独立处理遮罩、焦点、Esc 和滚动，关闭后恢复对应触发按钮且不丢失审批草稿。


### 8.4 实施与验证

- 三处权限范围复用同一编辑器、角色/数据弹窗、复制弹窗和权限目录；创建账号与权限变更共用系统内申请步骤，不再维护独立权限范围模板。
- 手工角色默认带入其全部功能，可在该角色绑定范围内取消或恢复勾选；复制角色功能始终完整锁定。复制结果不包含用户级直接功能权限，也不复制租户、组织和账号资料。
- 权限变更以归一化后的最终快照对比进入流程时的基线，集合顺序和重复 ID 不构成变化。
- 自动化命令：pnpm run test:permission-scope；在本地开发服务器运行时执行 pnpm run test:permission-scope:browser。
- 2026-08-09 已按 1440×900、1280×800 和首次访问 390×844 验证，详见 docs/UI_ACCEPTANCE.md 的 P06-01 至 P06-20。
## 9. SPEC-07：数据权限一级目录与目录内搜索

- 2026-09-08 起普通数据权限按 SPEC-13 升级为“业务目录 → 数据源 → 授权项”；前两层仅展开/收起，第三层勾选，默认展开；功能权限保持原有层级。
- 数据集文本只显示原始名称，不附加目录、范围或类型前后缀。
- 每个一级目录标题右侧使用现有线性图标风格的放大镜按钮；默认、hover、focus、active 和 disabled 状态沿用权限页按钮 token。
- 搜索按钮具备明确的 `aria-label` 和 tooltip；激活后在当前目录内容顶部出现搜索框并自动聚焦。
- 目录搜索状态相互独立，按当前目录数据源或授权项名称实时过滤；已选数据不因过滤丢失。
- 当前目录无匹配项时显示局部空态，不隐藏其他一级目录；关闭搜索清空当前关键词并恢复完整列表。
- 该共享交互覆盖权限申请三场景、角色新建/编辑、角色与用户只读详情；数据集很多时由权限列表区域滚动，底部操作始终可达。
- 目标视口继续为 1440×900、1280×800，首次访问补充 390×844 防溢出验证。

## 10. SPEC-08：权限申请填写信息字段规范化

### 10.1 范围与非目标

- 仅调整“权限管理 → 权限申请 → 填写信息”的五种字段组合：权限变更（内部/外部）、创建账号、启用/禁用账号（内部/外部）。
- “重置密码”的身份验证字段、校验和完成流程保持不变。
- 人员类型选择器继续位于字段区上方；它用于切换内部/外部字段组合，不计入截图定义的业务资料字段顺序。
- 权限范围、权限差异校验及既有审批规则不在本 SPEC 中调整。

### 10.2 统一字段矩阵

| 场景 | 按展示顺序排列的字段 |
| --- | --- |
| 权限变更（内部人员） | 申请人用户名/ITCode（自动带出）、被申请人 ITCode（必填）、被申请人手机号（选填）、被申请人邮箱（选填）、申请人直线经理（自动带出）、被申请人直线经理（必填）、申请原因（必填） |
| 权限变更（外部人员） | 申请人用户名/ITCode（自动带出）、被申请人用户名（必填）、关联人 ITCode（必填）、被申请人手机号（选填）、被申请人邮箱（选填）、申请人直线经理（自动带出）、申请原因（必填） |
| 创建账号 | 申请人用户名/ITCode（自动带出）、被申请人用户名（必填）、设置密码（必填）、确认密码（必填）、关联人 ITCode（必填）、被申请人手机号（选填）、被申请人邮箱（选填）、申请人直线经理（自动带出）、申请原因（必填） |
| 启用/禁用账号（内部人员） | 申请人用户名/ITCode（自动带出）、被申请人 ITCode（必填）、被申请人手机号（选填）、被申请人邮箱（选填）、申请原因（必填） |
| 启用/禁用账号（外部人员） | 申请人用户名/ITCode（自动带出）、被申请人用户名（必填）、关联人 ITCode（必填）、被申请人手机号（选填）、被申请人邮箱（选填）、申请原因（必填） |

### 10.3 交互、校验与数据规则

- “申请人用户名/ITCode”合并为一个只读字段，由当前登录用户自动带出；不再拆成两个输入框。
- “申请人直线经理”为只读自动带出；“被申请人直线经理”仅在内部人员权限变更中展示，由申请人填写并校验必填。
- “关联人 ITCode”仅在外部人员或创建账号场景展示，必须由申请人填写；内部人员场景不展示。
- 启用/禁用内部人员使用“被申请人 ITCode”，外部人员使用“被申请人用户名”；两者不可同时展示或校验。
- 手机号、邮箱明确标记选填；为空不阻止继续和提交。其余矩阵中标记必填的字段在失焦、下一步及最终提交时就近提示。
- 切换人员类型或申请类型后，隐藏字段不参与校验，也不得进入新申请载荷；再次显示时不允许错误地沿用另一人员类型的对象、关联人、密码或被申请人经理。
- 提交后的审批详情按相同字段 Schema 回显，不展示当前场景不存在的关联人或直线经理，空的选填联系方式显示“未填写”。
- 目标视口为权限后台既有 PC 范围：1440×900、1280×800；本 SPEC 不扩展后台移动端适配范围。
## 11. SPEC-09：用户管理资料、启停与权限变更流程

### 11.1 用户基本信息

- 用户编辑按“用户身份”“租户与账号设置”分区；人员字段与权限申请保持同一业务口径。
- 内部人员展示用户 ITCode、手机号、邮箱和必填的用户直线经理；外部人员展示用户名、手机号、邮箱和必填的关联人 ITCode。
- 用户基本信息不展示“用户显示名称”“用户账号”“内部 AD 账户”“是否绑定 ITCode”；底层稳定用户 ID 继续由系统维护，新用户显示名称默认取用户名/ITCode。
- 所属组织改为非必填多选，历史单组织数据进入编辑时归一化为数组；组织变化属于基本信息，由系统管理员直接保存。
- 有效期和备注继续作为用户管理主档字段；申请人、申请人经理和申请原因不作为用户主档编辑字段展示。
- 所属租户为必填多选。租户属于权限范围，租户变化与角色、数据权限变化使用同一权限变更审批流程。

### 11.2 操作语义

- 基本信息变化由系统管理员直接保存，不生成审批申请。
- 用户管理中的启用/禁用由系统管理员直接确认并立即生效，不生成申请单号、不进入审批列表；操作原因必填并写入历史变更供审计。
- 租户、角色、角色内功能权限或数据权限发生变化时，操作按钮显示“提交权限变更申请”；页面不展示手工申请单号字段，提交后由系统自动生成新申请单号并进入既有权限变更审批链。
- 同一次编辑同时包含基本信息和权限范围变化时，基本信息直接保存；权限范围保持原值，审批通过后再一次性生效。
- 同一用户已有待审批的用户管理权限变更时，权限编辑区只读并禁止重复提交；基本信息仍可编辑和保存。
- 用户管理“添加角色”直接复用权限申请的角色选择组件、搜索口径、默认详情、键盘焦点和关闭行为，不维护独立弹窗。
- 选择角色默认带入该角色全部功能和数据权限；勾选某项功能或数据会自动选中对应角色，取消某项权限不自动取消角色，取消角色会清理不再由其他已选角色提供的功能和数据权限。
- 功能权限只能在所选角色绑定范围内调整，不产生角色范围外的用户直接功能授权；确认后回写用户权限草稿，并与租户、角色和数据权限一起进入既有审批流程。

### 11.3 生效与失败边界

- 提交权限变更申请不得提前修改用户当前生效的租户、角色、角色内功能权限、角色数据例外或用户单独数据授权。
- 审批完成时按申请快照一次性更新租户、角色、角色内功能权限和数据权限，并写入“权限变更生效”历史记录；驳回或审批中不修改生效权限。
- 自动执行具备幂等标记，同一审批记录重复进入完成逻辑不得重复应用或重复写入历史。
- 用户对象不存在、申请缺少待生效快照或不是用户管理来源时，不执行用户权限落地。

### 11.4 视觉与验收

- 继续复用现有用户编辑弹窗、人员类型切换、租户多选、权限目录和状态样式；“添加角色”复用权限申请共享组件，不新增独立样式或全局视觉体系。
- 目标视口为 1440×900、1280×800；长内容由弹窗主体滚动，底部操作始终可达。
- 自动化命令：`pnpm run test:user-management`；并执行 typecheck、lint、build 和既有权限范围回归。
## 12. SPEC-10：外部用户登录前找回密码

### 12.1 范围与非目标

- 仅在“外部用户登录”的账号密码区域展示“忘记密码”；内部用户 ADFS 登录不展示该入口。
- 本流程用于外部用户登录前自助找回密码，不替代系统内“权限申请 → 重置密码”，也不恢复登录页自助注册入口。
- 不修改既有登录接口、登录成功跳转或内部用户认证方式。

### 12.2 流程与字段

- 流程固定为“身份验证 → 设置新密码 → 完成”。打开弹窗时带入登录页已填写的用户名；完成后回填用户名并清空密码。
- 身份验证支持手机号、邮箱二选一；切换方式时清空上一方式的联系方式、验证码和倒计时，避免跨方式复用。
- 身份验证字段为用户名、已绑定手机号/邮箱和 6 位验证码；手机号、邮箱先做格式校验。
- 获取验证码包含发送中、60 秒倒计时、重新发送、发送失败和验证码错误/过期状态；验证码有效期提示为 10 分钟。
- 设置密码包含新密码和确认新密码，长度至少 8 位，两次输入必须一致；提交中禁止重复操作。

### 12.3 接口、安全与预览边界

- 生产模式依次调用 `/api/admin/password-recovery/code`、`/api/admin/password-recovery/verify`、`/api/admin/password-recovery/reset`；只有校验接口成功后才能进入设置新密码。
- 验证码发送提示不暴露账号或联系方式是否存在；验证通过后仅展示脱敏手机号或邮箱。
- 新密码不回填登录密码框、不写入本地存储；成功后由用户主动使用新密码登录。
- 本地 POC 预览模式使用明确标记的演示验证码 `246810`；预览降级只在 `allowPreviewAuth` 开启时生效，生产模式接口失败必须停留当前步骤并显示错误。

### 12.4 视觉与可用性

- 弹窗复用登录页现有蓝色主色、8–10px 圆角、表单和按钮样式，不新增全局 CSS 或营销化背景。
- 弹窗支持遮罩关闭、Esc 关闭、打开后自动聚焦、关闭后焦点回到“忘记密码”入口；提交与倒计时状态具备禁用反馈。
- 目标视口为 1440×900 和 390×844；内容超高时仅弹窗主体滚动，操作按钮保持可达且不得横向溢出。

## 13. SPEC-11：二维数据表行列自定义授权

### 13.1 范围与统一原则

- 适用入口：角色管理的新增/编辑角色 → 数据权限 → 自定义授权；用户管理的新增/编辑用户 → 数据权限 → 自定义授权。两个入口都必须保留，不以角色授权替代用户直接自定义授权。
- 两个入口必须复用同一份数据集目录、数据模型、编辑组件、批量配置能力、校验规则和授权计算函数，不允许分别维护交互或业务逻辑。
- 权限申请或用户管理的“添加角色”详情如遇角色自定义授权，使用同一组件只读回显，避免将自定义授权错误展示为 0 项数据权限。
- 2026-08-20 评审后，单张数据集的行列关系固定为“与（AND）”：最终可访问范围为所选行权限与所选列权限的交集。界面不再提供 OR/AND 切换，也不提供“排除模式”。
- 本次不扩展后端真实鉴权接口；POC 使用本地 Mock 数据集目录与本地状态串联，但所有数据集、标签、维度、维度值和列字段均使用稳定 ID，便于后续对接接口。

### 13.2 数据模型与默认授权

- 自定义授权区域的主操作统一显示为“编辑”，不再根据当前是否已有授权显示“添加”。点击“编辑”进入同一份完整数据集维护弹层，不再直接添加一级菜单、条件组或自由输入条件。
- 每次打开编辑弹层时，以外层当前已保存规则创建一份完整草稿：数据集目录中的已添加和未添加数据集全部可见，均可在本次会话中勾选、取消、查看和配置；已添加数据集回显已保存的行列权限，未添加数据集保持未勾选且不预写外层规则。
- 弹层内的勾选、取消、逐表配置和批量配置只修改本次完整草稿。点击取消、遮罩或 Esc 关闭时丢弃整份草稿，外层授权保持不变；点击保存时以本次完整草稿一次性替换外层全部自定义授权规则，包括新增、修改和取消的数据集，不与旧规则做增量追加。
- 每张数据集使用稳定 `tableId`，包含名称、说明、`tags`、按业务维度分组的 `rowDimensions` 及 `columnFields`。行维度包含稳定 `dimensionId` 和其下的 `valueIds`；列权限保存稳定 `columnFieldIds`。
- 自定义规则按数据集保存：`tableId`、`rowSelections`、`columnFieldIds`，并以固定 `logic: AND` 兼容既有载荷。历史缺失、非法或 `OR` 逻辑进入本轮编辑模型时统一归一化为 `AND`，界面不再展示或保存可切换的 OR 规则。
- 勾选一张尚未添加的数据集时，默认选中该表所有行维度值和所有列字段。用户从“全量可访问”出发，通过取消勾选缩小授权范围。
- 同一张数据集在一次自定义授权中最多添加一次；已添加项在列表中明确标记且不可重复添加，删除后可以重新添加。
- 历史 Mock 中的扁平行字段按稳定映射归入“区域、业务类型、流量来源、终端”等业务维度；不同维度的值不得继续混排在同一列表中。

### 13.3 数据集查找、选择与单表配置

- 弹层左侧展示数据集列表，顶部固定使用一个统一筛选控件：左侧输入名称/说明/标签关键词，右侧展开标签多选下拉，二者共享同一外框和焦点状态，不再上下堆叠成两个输入框。数据集可展示 BU、业务类型等多个标签；关键词与标签两个筛选维度按 AND 组合，同一标签筛选维度内按 OR 计算，即数据集命中任一已选标签即可展示。
- 标签筛选按钮回显已选数量，并通过悬停提示展示完整已选标签；下拉支持逐项取消和一键清空。选项过多时仅下拉选项区内部滚动，不推动数据集列表或弹层整体。关闭并再次展开下拉时保留当前筛选回显；按 Esc 或点击下拉外部只关闭下拉且不清除已选标签。没有可选标签或组合筛选无数据集时，分别展示明确空状态。
- 左侧提供“全选当前结果”和“清空”操作。“全选当前结果”只勾选当前搜索和标签筛选命中的数据集，不误选隐藏项；“清空”取消当前草稿中全部数据集选择。界面不提供反选或排除模式。
- 右侧数据集标题区固定展示该数据集的标签；角色管理和用户管理的新增/编辑状态提供“编辑标签”，只读详情及角色选择回显不提供维护入口。
- 标签编辑支持复用已有标签和输入新标签；每个数据集最多 5 个标签，每个标签不超过 12 个字符，自动去除首尾空格且不允许重复。必须显式点击“保存标签”才生效，取消或首次按 Esc 只放弃标签草稿。
- 标签属于数据集目录元数据，不进入角色/用户的自定义授权规则。保存后只影响名称/说明/标签搜索和顶部标签筛选，不改变数据集勾选、行权限或列权限；未被任何数据集使用的标签自动从筛选区消失，当前筛选被移除时自动回到“全部”。
- POC 将标签按稳定数据集 ID 保存到本地目录状态并在刷新后恢复；后续对接后端时沿用同一数据集标签字段。标签存在未保存草稿时，切换数据集、批量配置或提交授权会明确提示先保存或取消，避免静默丢失。
- 数据集复选框只负责添加或移除选择；点击数据集名称、列表内容或“配置”只切换右侧当前详情，不能隐式改变勾选状态。切换详情时，各数据集草稿相互独立并持续保留。
- 点击尚未勾选的数据集名称时，右侧使用与已勾选状态完全一致的“逐表配置”结构，默认展开全部行字段、列字段、各级“全选/清空”和授权结果预览；状态显示“待完善”，初始权限数量为 0。行列复选框及所有“全选/清空”均可操作并实时更新结果矩阵；一旦用户选中任一行权限、任一列权限，或通过任一级“全选”产生至少一项权限，系统立即自动勾选左侧对应数据集，并将当前选择带入正式授权草稿。空状态下点击“清空”不勾选数据集；数据集自动勾选后即使再清空全部权限，也不自动取消数据集，仍由用户手动取消。未从右侧预配置、直接勾选左侧复选框时，仍沿用默认全选全部行列。
- 右侧单表配置按业务维度分组展示行权限，每个维度展开后多选具体值；列权限单独分区多选字段。行权限区和列权限区分别提供“全选”“清空”，并即时展示已选数量。
- 抽屉内以固定 AND 逻辑展示授权结果矩阵或等价摘要，清楚说明“所选行与所选列同时命中时可访问”；不显示 OR/AND 选择控件。
- 弹层使用完整草稿状态：点击取消、遮罩或 Esc 不修改外层表单；点击保存后才以草稿一次性替换外层全部自定义授权。所有已有和未添加数据集均通过主操作“编辑”进入同一维护界面，主入口不再使用增量追加；已有数据集卡片可保留逐表快捷编辑，但不得削弱完整数据集维护能力。
- 每张数据集可独立删除；删除最后一张后回到空状态。普通授权与自定义授权继续互斥，切换前须先清空当前另一类授权。

### 13.4 跨数据集批量配置

- 对两个及以上已勾选数据集提供独立“批量配置”入口。用户选择统一的行业务维度、维度值和列字段后，将规则一次应用到目标数据集，减少逐表重复配置。
- “批量行权限”只展示所有已选数据集共同拥有的维度值交集：维度 ID 与维度值 ID 必须同时一致；“批量列权限”只展示所有已选数据集共同拥有的列字段 ID 交集。交集按首个已选数据集的目录顺序展示，不混入任一数据集私有字段，也不只按中文名称推断同一字段。
- 已选数据集变化时立即重新计算行列交集，并自动移除不再属于新交集的已选字段、撤销上一次批量应用完成状态，要求用户基于新交集重新确认。任一权限轴没有共同字段时展示明确空状态，批量应用和最终添加保持禁用。
- 演示数据目录至少提供一组可完整验证的公共行列字段：三张示例数据集均包含“区域 / 全国”和“记录状态”，可完成三表批量配置；各表仍保留私有字段用于验证交集过滤。
- 只有所有已选数据集都同时包含本次所选全部行业务维度/值及全部列字段时，才允许应用批量规则。任一数据集不完整匹配时，本次批量应用整体阻止，不允许先更新部分匹配数据集；该校验作为目录异常、历史草稿或并发字段变化的兜底。
- 字段选择变化后立即校验全部已选数据集；若异常状态仍存在不匹配，展示红色错误提示和清单，至少包含不匹配数量、数据集名称及缺失的维度、维度值或列字段，同时禁用“应用到已选数据集”和底部“保存”。所有数据集完整匹配并成功应用后，才恢复最终提交。
- 批量结果必须回显到每张数据集的单表配置中。用户后续对单张数据集的调整覆盖该表之前的批量结果，不影响其他数据集；最终保存的是逐数据集展开后的规则，不依赖操作先后顺序重新计算。

### 13.5 校验、保存与变更识别

- 每张最终保存的数据集必须至少保留 1 个行权限值和 1 个列权限；缺少任一轴时，提示具体数据集和缺少项、定位到未完成项并阻止保存该规则。
- 外层角色保存和用户权限变更提交继续执行统一兜底校验，防止历史或异常数据绕过弹层校验。
- 角色与用户保存前统一归一化规则，固定为 `AND`，过滤目录中不存在的维度、维度值和列字段 ID，并对集合排序去重。
- 权限变化比较忽略规则临时 ID、数据集顺序、维度顺序和选项顺序；数据集、行维度/值或列字段的真实增删必须识别为权限变化。
- 用户管理提交后的审批快照继续完整携带用户直接自定义规则；审批通过前当前生效权限不变，审批通过后按既有流程一次性生效。

### 13.6 角色自定义权限冲突校验

- 用户可以获得多个角色，但所有角色来源在分配或最终提交前都要执行统一冲突校验，包括添加角色、复制他人角色及已有角色的合并结果。
- 两个角色不包含相同数据集时允许同时分配；包含相同数据集且归一化后的行业务维度/值与列字段集合完全一致时也允许同时分配。
- 两个角色包含同一数据集，但任一行业务维度、维度值或列字段不一致时判定为冲突，阻止本次角色分配或最终保存/提交。比较时忽略临时 ID 和集合顺序。
- 冲突提示必须明确展示冲突角色名称、数据集名称和差异摘要，并提供查看冲突详情及移除其中一个角色的恢复路径，不得只显示笼统错误。
- 用户在新增/编辑用户中直接配置的自定义授权属于用户级额外数据权限，不参与“角色之间”的冲突判断，也不能用于掩盖或自动合并角色冲突。

### 13.7 视觉、状态与验收边界

- 复用后台现有白底卡片、蓝色主色、8–10px 圆角、按钮和表单语义；组件样式必须局部作用，不新增全局覆盖。
- 数据集弹层必须 Teleport 到页面根层并高于角色、用户或审批弹层，避免嵌套弹层被父级遮挡；支持 Esc、遮罩关闭、焦点进入搜索框和关闭后焦点返回。
- 数据集列表、右侧配置区、行权限维度列表和列权限列表均设置稳定最大高度与明确滚动归属；长名称换行或使用 tooltip，弹层底部操作始终可达，避免多层滚动互相抢占。
- 覆盖默认空态、完整草稿打开/取消/替换保存、搜索/标签多选下拉与无结果、标签 OR 筛选、未选择数据集、单个/多个数据集、默认全选、全选/清空、维度分组、批量全部匹配、部分不匹配清单、行列未选完整、角色冲突、编辑回显、只读回显和长内容滚动。
- 目标视口为 1440×900 和 1280×800；数据集列表与右侧配置区分别承担纵向滚动，矩阵只在自身内部横向滚动，弹层不得横向溢出且无新增控制台错误。

## 14. SPEC-13 普通数据授权三级树（2026-09-08）

- 本节替代 SPEC-07 的普通授权两层展示约定，不改变自定义授权、功能权限、审批链路和权限生效规则。
- 统一为业务目录 → 数据源 → 授权项。前两层只有展开/收起按钮和数量，第三层才有复选框；展开、收起和搜索不得改变选中结果。
- 与数据源管理共用 mock：乐享运营包含运营指标查询、订单状态查询；GEO 看板包含信源引用查询；在职员工管理包含会员标签查询；企业客户管理包含线索池查询。
- 保留已有授权项 ID 与含义；会员标签项归入在职员工管理；订单状态新增三项 mock，不替换已有授权。该调整不涉及后端权限迁移。
- 兼容扩展现有 Domain 组件 PermissionDataDirectoryList，复用现有弹窗和 0825 视觉基线，不新增公共组件或全局样式。目录内搜索支持数据源、授权项名称，保留父级路径与局部空态，关闭搜索恢复完整列表及原折叠状态。
